# 持久化任务服务

`AgentScheduleService` 提供创建、分页列表、详情、取消、调度和重启恢复。数据通过 `TeaNekoAgentEasyData` 的 `agent.schedule.v1` 域保存在 Agent 专用表，沿用原数据库事务、行锁和重试。构造不启动调度，不访问外部平台。

宿主可显式传入 `EasyDataScheduleStore`、`Clock`、`Policy` 和动作注册表，再调用并等待 `start(ITimerService)`。默认 Spring 装配由 `AgentScheduleConfig` 提供，应用就绪时 `AgentScheduleLifecycle` 等待恢复并安装原 Core Timer 的一秒延迟扫描。生命周期由 Spring 调用 `close()` 终止。启动恢复和管理查询按一百条分页；运行时只查到期活动索引，按四个执行槽位的空闲数量领取，不扫描终态历史。慢动作只占自身槽位，不阻塞下一批发现，不新建线程池。一个部署只能有一个启动恢复拥有者；运行期的并发认领仍由数据库状态交换仲裁。恢复失败关闭调度并记录非敏感错误，原生命令得到不可用结果；恢复未完成时不接受创建。

## 原生命令和实际提醒

```text
/agent remind 2026-11-03T09:00:00+08:00 Asia/Shanghai 0 开会
/agent remind 2026-11-03T09:00:00+08:00 Asia/Shanghai 3600 每小时检查
/agent tasks
/agent tasks <上页游标>
/agent task <任务UUID>
/agent canceltask <任务UUID>
```

示例时间需替换为实际未来时间。时间要求带偏移，另传明确的 IANA 时区或固定偏移；偏移必须符合该时区在指定日期的规则。夏令时空洞拒绝，重复时段由显式偏移消除歧义。重复秒数为零表示单次。正文为 1–2000 字符，标题由正文前四十个 Unicode 码点生成。当前仅发送普通文本提醒，不调用模型或分派命令。

创建和执行需要当前 scope 已登记且启用。群提醒重新查询当前平台成员，未知角色、成员退出、用户目录映射变化或接口失败均拒绝，执行任务暂停；私聊只能投递到原 UUID 在原客户端的平台账号。目标由原生 scope 解析，不接受动作参数提供的新群号、客户端或身份。查看和取消允许本人或当前平台群管理员，关闭 Agent 后仍可管理已有任务，普通成员看不到其他人的任务。列表按页内计划时间排序，页间仍沿用稳定 ID 游标，不宣称全表按时间分页。

实际提醒使用原发送器，关闭自动重试和发送失败持久化补发，等待平台真实回执及有效消息 ID。空响应或缺失消息 ID 进入结果不明，停止该任务，不自动再次发送。已有外部发送开始后的取消不能保证撤销；平台没有幂等提交能力时不能宣称网络意义上的恰好一次。

## 创建及查询

自然语言入口为当前真实消息的 `/agent chat`，例如：

```text
/agent chat 10分钟后提醒我喝水
/agent chat 每10分钟提醒我检查进度
/agent chat 明天09:00 Asia/Shanghai提醒我开会
/agent chat 2026-11-03 09:00 Asia/Shanghai提醒我开会
/agent chat 查看我的任务
/agent chat 查看任务 <任务UUID>
/agent chat 取消任务 <任务UUID>
/agent chat 查看任务下一页 <上页游标>
```

这是有界原文解析入口：完整匹配后产生纯数据候选，仍经同一原生权限和存储防重；不调用额外模型。普通聊天继续进入原 Agent；模型或历史引用不能提供这条入口的当前原文，派生命令也不走此捷径。只在当前 scope 已登记、启用时执行自然语言任务，禁用后的管理可用上方显式命令。

相对时长固定基于平台原消息发送时刻，重试不重新以当前时间计算，显示时区明确使用 UTC。支持秒、分钟、小时、天，单次最多一年，固定重复至少六十秒。日历表达支持今天/明天/后天加 HH:mm、ISO 本地日期时间及带偏移时间；可在表达后明确写 ZoneId，或由 OWNER 设置 `/cfg set agent taskTimeZone Asia/Shanghai`。该配置默认为空，不猜测本地日历时区；原文明示的偏移优先，额外提供地区时区时还须验证一致性。夏令时空洞或重叠、模糊的“早上”等表达只要求澄清，不创建任务。不支持任意同义表达或任意日历周期，正文按字面文本提醒，不执行其中的命令。

`create(requestId, spec)` 的 ID 应从真实消息及操作稳定生成，不能每次重试随机生成。规格包含标题、真实 `AgentActorContext` 创建者及目标、已安装动作名、有界参数、首次 `Instant`、明确 `ZoneId` 和固定秒数间隔。首次时间需在未来十年内。自然语言中的“稍后”“周五早上”等含糊时间必须先澄清，不能交给服务猜测。

间隔为零代表单次；重复间隔为六十秒至一年。固定秒数间隔不等于带夏令时规则的“每天本地九点”，目前没有日历重复规则。同一个 ID 和原规格重放返回已提交任务，不复活已取消或完成状态；同 ID 不同规格拒绝。

`detail(id, actor)`、`cancel(id, actor)` 限定当前原生 scope，并通过实际权限策略检查。`list(actor, after)` 按原始存储页返回可见任务和继续游标；因其他 scope 记录而出现空页时仍可能有下一页。`TaskPresentation.card/list` 提供普通消息文本，宿主可按消息限制拆成转发节点，不展示动作参数。

## 执行与恢复

- `Policy` 必须查询当前注册、启用、动作能力和真实创建者权限，读取及取消还应验证归属或当前 scope 管理权；查询失败拒绝。保存的创建者仅用于重新查询，不是系统任务的身份授权。
- 默认装配先执行公共身份和归属检查，再执行动作自身的创建/执行策略。插件通过 `AgentTaskAction` 同时贡献动作与窄策略；不能沿用只接受 remind 参数的校验，也不能跳过公共检查。读取和取消不要求动作插件仍启用，方便管理遗留任务。
- 注册的 `Action` 必须在每个副作用前等待收到的 `guard`，并以任务 ID 和计划发生时间为幂等键。服务不自动安装文件、代码或命令执行器，不赋予系统任务 DEBUG。
- 认领使用持久化状态和修订号交换，只有实际交换成功的调用方可执行。取消提高版本；等待中的旧动作在 guard 处停止，迟到结果不能覆盖取消。已经开始的外部动作无法保证撤销，检查和外部提交之间的原子幂等边界由后端提供。
- 执行完成才推进下一次发生；异常、空结果或结果不明转为 `INDETERMINATE`，不自动重试；执行器明确拒绝或当前权限不可确认转为 `PAUSED`。暂停记录保留，目前需取消后显式重新创建，不会自行恢复。
- 启动先分页恢复，再安装 Timer。旧 `RUNNING` 标为结果不明；已过期单次标为 `EXPIRED`，重复任务跳到严格晚于当前时刻的下一次，不批量补跑。正常运行迟到超过三十秒也跳过当前发生。
- 到期索引与任务状态同事务维护；升级时启动恢复自动补齐已有活动记录的索引，无需手动修改 SQL。

当前已接入默认 Spring 生命周期、原生命令、当前原文自然语言候选和实际提醒发送适配。自动入口及三级策略见 [消息入口](../../integration/message/README.md) 和 [自动触发门控](../../runtime/trigger/README.md)。真实数据库的索引规模、执行吞吐及平台发送仍需实机验收；离线验证没有向真实客户端发送消息。
