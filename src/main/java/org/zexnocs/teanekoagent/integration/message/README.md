# 原生自动入站、图文输出与历史采集

`NativeAgentReceiver` 监听原有 `TeaNekoMessageReceiveEvent<?>`，在原业务执行器中检查当前作用域配置、客户端自身身份和原生信号，再交给 `AgentAutomaticGateway`。使用原 Factory、顺序邮箱、LLM、工具、防重账本和平台发送器，没有第二套模型循环或线程池。

## 启用与触发

```text
/cfg reg agent
/cfg set agent enabled true
/cfg set agent mode PASSIVE_BASIC
/cfg set agent triggerNames 茶猫,TeaNeko
```

实际模型与凭据仍从本地配置读取。登记并启用后，私聊和群临时私聊的普通图文直接触发回复，不需要 @；群聊最低被动模式仍只响应原生 @ 机器人或引用机器人。群聊称呼只有 PASSIVE_CONTEXTUAL/ACTIVE 才生效，需完整出现在正文开头，随后为空白或明确标点，不能仅靠任意子串匹配。三级、续聊、静默及冷却配置见 [触发门控](../../runtime/trigger/README.md)。

机器人自身平台 ID 必须由客户端 `ITeaNekoToolbox.getSelfPlatformId()` 提供。OneBot 使用连接生命周期确认的 ID，未知时不启用自动入口；其他客户端未实现时默认未知，不从用户文本猜测。机器人自己的回显跳过。引用只按已知消息 ID 补取，校验原作者、客户端、scope 和原消息 ID；补取失败不增加触发权限，不把引用正文交给模型或当作当前用户授权。

被动模式中的普通旁观消息不调用模型；采集开启时可以按需初始化当前有效空间并记录文本，采集关闭时不因此初始化空间。ACTIVE 模式可以另行提出自主候选，规则见下文。未登记或禁用时不进入自动业务。实际命令目录中的普通/正则指令交原命令接收器，原生提及不使已知命令误入 Agent；未知斜杠正文按普通消息处理，仍须满足当前触发规则，不自动获得命令权限。不取消其他插件事件。新版[内部客户端](../../../teanekoclient/agent/README.md)只发布响应事件，不回灌普通入站；旧包已移除。

## 原生图文输入

每条送给模型的原生用户消息先附带独立上下文文本块，包含 client ID、scope ID、消息 ID/时间/类型、TeaNeko 用户 UUID、平台发送者 ID、昵称、群名片、群号和已知会话名称。显示字段经过 JSON 转义和长度限制，只是参考数据，不是指令或授权；未知名称明确为空。上下文不加入 `AgentUserText` 或明确记忆意图，聊天窗口只显示正常回答。OneBot 的当前群名称由[平台能力](../../../teanekoplugin/onebot/common/agent/README.md)补充，查询失败标记未知，不阻止聊天。

上下文还包含宿主工具箱提供的 selfPlatformId、由原生提及计算的 mentionedSelf 和 mentionedUserIds。selfPlatformId 是正在回复的机器人账号，mentionedSelf=true 明确表示“用户在 @你”；这些 ID 是平台账号，不是 TeaNeko UUID，all 表示全体成员。未知机器人 ID 为空，不通过昵称或用户文字猜测；判定自身提及先检查完整原生列表，再限制向模型展示的提及数量。命令与自动入口共用这一投影，原文、负载摘要和明确记忆授权不被元数据改写。

`NativeMessageInput` 在触发和排队前冻结当前原文、图文顺序、原生发送时间与完整负载摘要。支持纯图片及文本/图片混排；原生提及、引用和转发节点不成为图片、当前文本凭据或引用正文。每条最多四张图，文本最多 65536 个 Java 字符，图文引用总量最多 2097152 个字符；模型的完整输入预算可能更严格。

图片只接受 Core 已支持的 HTTP(S) 或带明确媒体类型的 data URL，不读取 file 路径、不猜测平台文件名、不下载图片，也不接收缺少媒体类型的裸 base64 引用。具体模型仍须明确声明图像角色和细节能力；文本模型不会自动获得视觉能力，非法或不支持的图像不丢弃后假装处理成功。窗口保留的助手图片在后续轮次同样受该模型的输入角色声明约束。

## 独立旁观采集

`historyCaptureEnabled` 控制当前 scope 的原生文本采集，沿用原历史服务和 Agent 专用 EasyData。采集先固定空间/代次及人格，保留真实 UUID、来源 ID 和平台发生时间，不调用模型或生成事实。文本消息先提交采集，再决定是否触发；原命令保持原入口的正文语义，不由普通入站重复采集。纯图片没有字面文本时不写文本历史，图片内容及 URL 不冒充历史正文。

采集、模型准入与工具调用使用分开的持久化回执种类，同一采集来源只取得一次执行权；重复、冲突或旧结果不明不换新上下文重做。自动轮次继续使用采集时的引用和人格，排队后发生切换则停止，不刷新成新代次继续。轮次历史记录与采集使用同一原文和真实时刻，重复只保留一条；旧独立宿主没有平台时刻时仍明确标记为处理时间估算。历史保存不等于消息已经被模型处理或平台交付。

## 执行与发送合同

2026/11/03：默认实例安装 expression 能力时，命令和自动回复可一次输出文字分段与等待信封，后端先完整编译再逐段交付；三个 Agent 入口共用目标顺序。旧图文/JSON、真实票据及逐段回执继续保留，当前协议和开关以[表达模块说明](../../../teanekoplugin/agent/expression/expression/README.md)为准，素材及客户端表情尚待后续批次。

每个自动请求固定真实 UUID、client/scope、消息 ID、当前原文和触发票据。票据接入原 `AgentAccessGate`，模型、工具、历史提交及交付检查沿用原管线，失效时明确拒绝；无需把服务或权限句柄放入组件。命令工具继续受 `commandToolsEnabled` 和原权限限制，使用真实原生来源租约，不构造 DEBUG。当前原文明确事实工具仍按原有独立授权规则执行。

同 client/scope/消息的自动准入先写专用持久化账本，重复投递或入口重建不重新运行模型、工具或发送。不同正文占用同一来源不能覆盖原回执。已开始但未完成的操作不自动重试，不在重启后恢复模型循环。

`AgentReplyPlan` 仅消费 SUCCESS 正式答案中的明确文本或图片类型，不发送推理、工具诊断或供应商透明状态，也不把正文中的 URL、Markdown 或路径解释成图片。无正式内容放弃回复。计划先完整验证，最多三十二段、四张图，文本总量最多 64000 个 Java 字符、每段最多两千，保持 Unicode 代理对完整；图片引用总量最多 2097152 个字符。保持图文顺序，标准 data 图片转换为平台发送器已有的 base64:// 引用，不使用磁盘中转。这是显式图片内容的发送适配，不代表默认模型新增了图片生成能力。

各段顺序发送，前一段真实回执成功后才开始下一段。每段发送前重新观察原结果，复核原引用/人格/资料、票据和实际目标；任何一段失败停止余下部分，不撤销已发送内容。当前仍不支持的正式内容类型使计划整体失败，不静默略过。

默认逐段回执保存在独立 agent.delivery.v1 域，只有返回有效平台消息 ID 才确认平台接受。命令、自动回复与自主发言共用账本；重启不补发未决段，近期记忆只投影已确认部分，未知状态不能当作发送成功。确认不表示对方已经阅读；账本、保留期和替换端口见[分层记忆](../../../teanekoplugin/agent/cognition/memory/layered/README.md#明确保存与平台回执)。

发送使用原客户端发送器及平台状态链，关闭自动重试和失败持久化补发。平台没有幂等提交能力时，不能声称网络意义上的恰好一次。只有全部正式回复交付成功才延长该发起者续聊窗口；失败或无发言释放票据。来源租约、自动实例和借用服务的拥有关系分别结束，不关闭原邮箱或共享执行器。

## 模型选择回复形式

普通正式图文仍按原有规则投影；模型也可按系统说明返回以下严格信封，选择引用、只提及当前发起者或普通分段。`messages` 为空表示弃言。未知字段、重复键、非法版本或任何无效段落使整个计划失败，发送前不输出部分结果。

```json
{"teaneko_reply":1,"messages":[{"mode":"reply","text":"引用当前消息"},{"mode":"at","text":"只提及当前发起者"},{"mode":"plain","text":"单独发送这一段"}]}
```

每段最多两千字符，最多三十二段，顺序由模型选择；不接收任意用户、scope 或消息 ID。私聊的 at 沿用原发送器行为，不虚构群提及。显式 `/agent chat` 和自动回复共用计划及发送器，每段前复核原结果。直接服务或内部 Sender 只返回正式计划内容，由调用方决定是否发送；不生成普通入站事件。

## 定时与接话配置

```text
/cfg set agent mode ACTIVE
/cfg set agent activityTimeZone Asia/Shanghai
/cfg set agent proactiveTimedEnabled true
/cfg set agent proactiveInterjectionEnabled true
/cfg set agent proactiveIntervalSeconds 900
/cfg set agent proactiveAttemptCooldownSeconds 60
```

两种候选开关默认 true，但只有已登记、启用的 ACTIVE scope 才会运行；默认最低被动模式不启动自主发言。定时间隔默认十五分钟，尝试退避默认一分钟，两者允许 60–86400 秒。另有成功发送冷却默认十五分钟及本地时区静默规则，见 [触发门控](../../runtime/trigger/README.md)。定时与接话共用原票据、成功冷却和尝试退避；模型弃言、失败或结果不明也受尝试退避约束。

`ProactiveCoordinator` 在应用就绪后向原 Core Timer 注册三十秒扫描，不另建线程池。每次轮转至多四个 scope，服务同时至多两个自主任务，忙时跳过，不积压候选。进程内至多保存一千个目标。群目标从现有配置和客户端目录重建；私聊目标只从本进程实际接收的消息确认，不根据只有 UUID 的配置键猜测平台用户。首次发现、间隔变化或重启均等待完整间隔，错过的定时不补跑；调度状态与退避不跨重启保存。

未触发被动回复的原生文本可以提出接话候选，纯图片不独立提出接话。`ProactiveService` 使用无 UUID、无平台用户权限的 SYSTEM 身份和独立控制，最多一次模型请求、零工具执行及三十秒总截止时间；输出额度取所选模型配置，可选总预算必须完整预留输出，不足则拒绝。不继承人类 DEBUG，不运行命令工具。安装 memory 且历史读取开启时，最多取当前有效边界内最近八条文本并截断标记；接话当前原文另作低信任资料。没有任何可用文本时直接弃言，不调用模型。

模型必须返回严格的 `speak/text` JSON 信封，可明确弃言；重复键、多余字段、非法正文或非文本结果均拒绝发送。固定目标、当前配置、人格和原 Prompt 资料在执行及交付前复核；安装 memory 时还复核空间代次，旧轮不刷新成新引用继续。每个定时发生/原生接话来源先取得专用持久化 PROACTIVE_ENTRY 回执，重复或结果不明不自动重做。未安装 memory 时仍保存请求、目标及来源摘要用于防重，不解析或写入记忆空间。

只发送通过验证的短文本，沿用原发送器并等待实际回执，不自动重试或失败补发。实际发送成功才记成功冷却，并把正文作为 SYSTEM 来源的助手历史追加；控制 JSON 不进入历史。发送后历史写入失败仍记为已交付，不重复发言。网络确认不明不代表平台没有收到，取消也不能撤回已发生的发送。

## 当前范围与后续

已完成自动图文入站、原生工具来源、旁观文本采集、模型选择回复形式、有序图文输出和可弃言的定时/接话候选；[脱敏运行监控](../../runtime/monitor/README.md) 已接入原轮次和自主交付，[内部 Client/Sender/Response](../../../teanekoclient/agent/README.md) 已迁移，旧包已移除。私聊也按当前级别判定，不因私聊而绕过最低被动规则。有界自然语言任务使用明确的 `/agent chat` 或任务命令，见 [任务说明](../../../teanekoplugin/agent/automation/schedule/README.md)。

离线验证复用真实 Agent/LLM/命令/历史管线、EasyData 事务夹具及 FakeClient，覆盖自动入站、多段全文、图文协议顺序、纯图片、显式图片发送、原文时间、防重、历史开关和换代保护。没有发送真实消息；实际 OneBot 图片引用/发送显示/回执、MySQL、完整 Spring 启动及性能仍需实机验收。
