# 三层持久记忆与自动画像

当前版本：4.6.1-l。三层记忆、观察式人格与新域到期维护已经接通；显式入口统一及最终接入收尾仍按 [实施计划](../../../../../../../../docs/plan/4.6.1-layered-memory.md) 继续开发。

默认完整装配将 teaneko.agent:layered-memory 和 teaneko.agent:long-memory 安装到使用默认能力的实例。显式选择 features 的实例需分别加入所需能力，才能向模型提供恢复资料和长期工具。

## 实际数据与行为

短期记录和原历史记录在同一个 EasyData 事务提交；任何写入失败一起回滚。每条消息保存原作者 UUID、完整 client/scope、实际事件时间、角色和采集时人格；来源重投不增加序号或延长保留期。短期分区包含 namespace、绑定版本和 generation，不包含人格身份，因此单纯换人格仍可追溯原消息。

近期资料默认只来自当前 scope，标明来源和精确时间。USER 是收到的发言；ASSISTANT 是生成但尚未确认平台发送的答案，不能当作用户自述或成功发送回执。本批不新增平台送达状态持久化。

每次最多读取 24 条近期消息和 6 段中期片段，分别最多装入 6000 字符的完整资料；单项过长时省略，不截断成另一句话。近期注入排除当前原文和已被中期覆盖的消息。资料由原 Prompt 总预算决定最终采用，有限窗口不代表完整历史。重启后从数据库读回，不恢复旧模型调用、工具副作用或未完成发送。

中期片段记录固定源序号区间、输入指纹、事件范围、简短及详细摘要、实际生成时间。普通时间显示概略月份，重要日期由摘要保留原精度；处理时间不能冒充事件发生时间。资料只作为 USER 参考数据，继续接受当前开关、原引用、片段有效期和插件版本复核。

## 自动压缩及恢复

后台在原调度器扫描持久分区目录，最多一个在途压缩任务。未处理消息达到数量阈值，或可压缩旧段达到字节阈值时领取任务，保留最新若干消息。通过原 SUMMARY 活动门控执行一次无工具 LLM 请求，预算独立于前台，仍受原模型能力和 token 预检限制。

领取的连续输入和租约写入数据库。生成后复核原消息指纹、代次、租约和原始保留期；摘要必须符合结构、容量并缩小输入。中期片段与压缩水位同事务提交；其间新追加的尾部不会阻止原前缀提交。旧租约、clear 后的旧代次或策略撤销均不能交付迟到结果。

失败不推进水位，按 30 秒起步、最长一小时的有界退避重新尝试；次数计入持久状态。原始数据与未完成状态仍在，重启后租约到期可重新领取。关闭停止调度并结束自有控制，原模型或数据库已经发生的工作不因此承诺回滚。

原始消息到期后不再用于新摘要；已过期源的跳过位置和成功压缩水位分别保存，不能声称过期消息已被记住。后台维护逐批回收已到期正文，原历史清理继续独立运行。没有足够旧消息的近期尾部继续留在短期，不强制每轮调用模型。

## 配置

前缀 tea-neko.agent.memory.layered.：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| enabled | true | 启用分层资料和后台压缩；不替代原历史采集开关 |
| trigger-messages | 12 | 未处理消息数量触发阈值 |
| trigger-bytes | 32768 | 候选旧段紧凑 JSON 字节触发阈值，与数量条件满足其一即可 |
| keep-messages | 4 | 压缩时保留的最新原始消息数 |
| batch-messages | 16 | 单次压缩的连续消息上限 |
| max-input-bytes | 131072 | 整个摘要模型消息输入的字节上限，仍受实际模型 token 上限约束 |
| timeout-seconds | 45 | 本次生成及提交观察的总时限 |
| retention-days | 90 | 中期片段可用于注入的保留期 |
| poll-ms | 5000 | 目录扫描周期 |

压缩沿用 scope 的 historyCaptureEnabled 和 autoSummaryEnabled；近期读取同时要求 historyReadEnabled 和 memoryReadEnabled，原 Agent 登记和启用仍是前提。长期读取要求 memoryReadEnabled，学习要求 memoryLearningEnabled，本人维护要求 memoryAddEnabled。新建 scope 的 memoryLearningEnabled 默认 true；已有数据库中显式保存的 false 继续生效，需要自动学习时通过原配置入口开启：

```text
/cfg set agent memoryLearningEnabled true
```

本地 tea-neko.agent.memory.long-term.enabled=false 可同时关闭新长期生成、读取和维护；关闭 layered.enabled 也停止新长期功能，不改动旧事实和旧人格。关闭学习不删除现有长期记忆，不阻止已经允许的短期采集。

人格观察沿用独立 personalityLearningEnabled；开启观察后，即使关闭 memoryLearningEnabled，后台仍可消费新中期片段的合格人类表达，但不会提交事实候选。默认开启的联合分析不会额外调用一次模型；没有当前人格合格样本且事实学习关闭时，直接完成空筛选。观察具体规则、查看工具和回退方式见[人格说明](../../personality/README.md#持久观察式人格)。

默认分层装配启用时停用旧内存摘要生成，避免重复消耗同一聊天。关闭分层功能，或独立宿主未装配分层存储时，原内存摘要保留。

## 数据和扩展

数据继续放在 tea_neko_agent_data 的 agent.memory.layers.v1 域：short: 保存消息，source: 防重，streams 为恢复目录，states 为租约与水位，medium: 为片段。业务只访问专用 EasyData DTO，不直接操作 Repository。

长期派生数据位于同表的 agent.memory.long.v1 域。共享键只包含 namespace 与 generation；来源 client/scope 和绑定版本保存在证据链，不用于隐式过滤长期召回。jobs 为持久整理租约和水位，entries: 为权威记录，subject:/term:/recent:/family: 为索引，changes: 为本人操作回执，blocked: 为旧证据抑制。原事实与人格域继续保留，本批不将旧事实自动导入新索引。

## 到期维护与旧代次回收

维护独立于采集和学习开关；关闭学习、分层注入或长期读取不延长已保存数据的有效期。默认每十秒串行维护实际实现 IMemoryMaintenance 的数据域，前批未结束不重叠启动，不调用模型。单域失败时回滚该域的变更及游标，其他域仍可继续；重启从已提交进度恢复。倒序域分页在到达末页后轮转，持续新增数据不会无限延长当前扫描轮。

```properties
tea-neko.agent.memory.maintenance.enabled=true
tea-neko.agent.memory.maintenance.interval-ms=10000
```

短中期每批维护一个分区，扫描至多十六条短期与八段中期。短期正文和来源索引一起回收，当前分区保留 last 序号、水位和作业，新的消息不会重新从一开始编号。未压缩消息只回收已处理区间或连续到期前缀，避免删除中间行破坏后续压缩；被有效前项挡住的到期消息会在后续压缩或前项到期后回收。原始消息到期不撤销已经合格的长期结论。中期按当前保留期回收，租约内已经到期或被回收的来源不能迟到提交。

长期每批最多检查八个域内记录。当前代次仅精简到期原话、修正失效索引，保留事实正文、公开版本、来源摘要、人工锁定、遗忘墓碑和幂等回执。已 clear 的旧 generation 逐批回收正文、作业、索引、旧回执及旧墓碑；不清除当前代次，也不通过重新绑定改变原任务目标。原话精简不改变公开内容 revision，不使正在使用的同内容资料无故失效。

agent.memory.lifecycle.v1 保存空间/分区的无正文定位标记，新采集同事务登记，已有分区在维护时补登记。原目录删除后仍可判定旧作业和共享索引归属；未知归属保守保留，不猜测后删除。定位标记不含对话、密钥或用户事实，继续保留用于安全维护。旧 namespace 的原 fact 管理回收入口不变。

人格观察按原保留期精简样本，失效模式回收后保留无原话的采用水位；可写人格集合释放到期补正容量，不改动不可变备份。具体边界见[人格说明](../../personality/README.md#持久观察式人格)。关闭维护只暂停物理回收，不让到期内容重新可读。关闭服务不声称取消已经开始的数据库事务。

## 从中期到长期

同一后台处理器先整理已就绪的中期片段，再压缩旧消息；两个阶段共用单个在途任务、一次模型调用和总时限。每批最多四段；一段空闲十分钟后也会进入整理。生成走原 LEARNING 活动及统一模型交互，无工具，输出事实、偏好或事件；有当前人格样本时，联合对象包含 memories 和 styles 两个数组。空候选也是有效的完成结果。重复运行不会再学习已完成水位之前的闲聊，关闭的学习域不会在未来重启时自动补学已跳过旧段。

事实和偏好必须引用对应作者的真实 USER 消息连续原话；提交事务重新核对消息、主体、片段范围、保留期和输入指纹。助手答案不能变成用户事实。事件可以引用中期摘要，但 subjectId 为空，不冒充个人画像。普通召回只给公开结论、状态、版本和概略月份，不输出其他群原聊天或原话证据。重要时间必须逐字来自已核对的引用。

同主体、类型、属性、正文重复时合并来源；明确 REPLACE 且来源较新才替代同属性旧值，人工锁定或时间倒置时保留冲突，CONFLICT 不能作为确定结论使用。自动画像是当前主体有效事实和偏好的投影，不维护另一份无来源的画像正文。

普通聊天先注入至多八条本人画像，再补至多八条本轮关键词命中项，两个片段分别限四千字符并跨来源去重。索引最多扫描 256 个候选，受限时明确 limited，不把空页声称为完整不存在。当前是字面关键词检索，没有新增向量库。每次发送或重放前检查条目版本，已经纠正、遗忘或替代的旧资料不能继续采用。

## 注解工具与本人维护

所有 client 默认可用，仍要求实例允许 TOOL 活动、安装 long-memory 能力以及当前真实作用域权限：

| 工具 | 用途 |
| --- | --- |
| memory_search | 按 query、可选 subjectId 和 limit 检索当前共享 namespace 的自动长期结果 |
| memory_user_profile | 默认读取当前用户的自动画像，可显式指定共享空间内的用户 UUID |
| memory_correct | 根据已查询的 id、revision 纠正本人条目，锁定人工结果 |
| memory_forget | 根据已查询的 id、revision 遗忘本人条目并留下墓碑 |

维护工具仅在本轮真实原文以“纠正/请纠正/更正/请更正”或“忘记/请忘记/删除记忆/请删除记忆”开头时提供；“你是不是忘记我了”不会授权删除。先查询目标，含糊时澄清，不能修改他人条目。真实用户 UUID、空间和来源从宿主取得，模型不能通过参数自报。回执与修改同事务保存，同一原工具调用重试返回相同结果，换参拒绝。

本人维护轮次不预先注入新长期画像，改由查询工具取得原版本，避免本轮维护成功后自动注入的旧版本让同一轮次失效。普通聊天仍检查已采用资料的原版本，不能把失效投影静默更新成其他内容。

纠正和遗忘保留原始聊天；派生抑制采用原主体/片段及真实平台消息来源。同一旧证据重新绑定、重导入或换正文也不能自动恢复已遗忘内容；同片段中该主体的其他候选以及依赖被抑制来源的事件也会保守跳过。新消息不自动解除人工锁定或恢复同一已遗忘正文。若要恢复，需通过明确的本人纠正操作；本批没有整库自然语言删除或跨用户维护能力。

ILayeredMemoryStore 和 ILayeredMemoryCompressor 分离持久化与生成；可以替换摘要后端，不重写调度器。自定义存储须同时提供可靠采集适配，不能仅替换读取端口后假定默认历史事务会为其写入。旧独立 EasyDataHistoryStore(data, mapper) 构造保留原语义，不自动采集新分层数据。

ILongTermMemoryStore 与 ILongTermMemoryConsolidator 分离证据提交、索引和模型选择；LongTermMemoryAccess 为资料与注解工具共用的可信入口。替换生成器仍需经过原处理器的学习/引用复核与事务端口证据校验，不以模型返回成功代替真实提交。新模型适配和存储均在构造期不进行 I/O。

维护不迁移旧事实，不回收有效长期结论、无期限补正或不可变备份；原历史按自身保留策略维护。离线测试使用现有事务夹具；真实 MySQL 事务代理、锁、索引与真实模型摘要质量仍需实机验收。
