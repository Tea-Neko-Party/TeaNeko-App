# 自动触发门控

`AgentTriggerGate` 将触发判定、并发准入和实际交付记账与模型、记忆、调度、平台发送分开。默认 Spring Bean 读取现有 `/cfg agent` 的当前配置，由[平台自动入口](../../integration/message/README.md) 提供原生消息及定时/接话信号并消费票据；门控本身不调用模型。

| 模式 | 消息触发 | 自主候选 |
| --- | --- | --- |
| PASSIVE_BASIC | 私聊直接对话；群聊原生 @、引用机器人 | 拒绝 |
| PASSIVE_CONTEXTUAL | 基础触发、明确称呼、同发起者成功回复后五分钟续聊 | 拒绝 |
| ACTIVE | 与中级相同 | 允许定时或接话候选，仍受冷却与静默约束 |

旁观用户的普通消息不借用其他人的续聊窗口；未登记、禁用及机器人自己发出的消息拒绝。宿主不能根据文本中“已 @ 机器人”等声明生成提及信号。显式命令、用户创建的提醒任务不经过主动发言冷却。

私聊包含群临时私聊，由原生消息类型设置 `Signal.privateConversation`；不从 scope 字符串或聊天正文猜测。旧六参数信号构造保持群聊行为。私聊仍检查登记、启用、自身消息和票据占用，原命令不会同时触发普通聊天。

## 配置

```text
/cfg set agent mode PASSIVE_CONTEXTUAL
/cfg set agent activityTimeZone Asia/Shanghai
/cfg set agent proactiveCooldownSeconds 900
/cfg set agent proactiveQuietStartHour 23
/cfg set agent proactiveQuietEndHour 7
```

配置权限沿用原 OWNER 边界。默认模式仍为最低被动，主动冷却十五分钟，静默从 23 时至次日 7 时；时区明确默认 UTC，可配置为当地 ZoneId，不读取服务器默认时区。静默起止相同表示关闭静默，静默仅限制自主候选，不限制被动直接回复。应用就绪后 ACTIVE 的候选由平台协调器装配，独立开关、间隔与尝试退避只在平台说明维护。

## 宿主调用合同

1. 先完成原生身份和信号识别，调用 `acquire(signal)`；空结果时不要启动模型或副作用。
2. 票据保留原配置，仅六十秒有效。模型、写入及实际发送前都调用 `verify(ticket)`，同时继续经过原 Agent 的权限、引用/代次和预算检查；触发票据不替代这些授权。
3. 实际交付成功后调用 `finish(ticket, true)`，失败或放弃在 finally 中调用 `finish(ticket, false)`。失败释放占用但不延长续聊窗口；迟到旧票据不能释放新票据。成功主动发送记录冷却，成功被动回复只更新该发起者的续聊窗口。

同一 scope 同时最多一个自动触发票据，过期旧票据不可发送或记账。内存最多保留一千个 scope，每个 scope 最多二百五十六个有效续聊用户；容量不足拒绝，过期窗口按需回收。不持久化续聊状态或冷却，重启后窗口清空；平台宿主需在准备就绪后启用自动入口，并对失败自主任务安排退避，不能把门控当作自动重试策略。

当前离线验证覆盖级别、同人窗口、并发占用、未登记、跨午夜静默、主动冷却、过期及旧票据保护。S9 已接入实际平台消息、定时/接话、SYSTEM 独立轮次和真实发送回执等待。
