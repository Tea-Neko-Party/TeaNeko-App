# 社交插件

插件 ID：`agent.social`，依赖 `agent.cognition`。提供 `affinity`、`mood`、`proactive`、`care` 与 `private-contact` 组件。各项能力仍须显式装配，并在实际调用时复核当前聊天的访问、发送和预算边界。

主动协调与发送服务通过 `IPluginLifecycle` 管理后台任务。插件停用或依赖不可用时停止接收新工作；原参数和持久数据保留。私聊发送只使用真实来源的既有客户端映射，`contact` 下的 `IPrivateContactTransport` 契约与适配器均由本插件维护，复用官方客户端的通用发送能力。

社交资格组合 Agent 的通用组件配置查询和认知插件的记忆读取规则；跨聊天回忆直接使用认知读取入口，不反向依赖社交插件。

## 主动活动时限

聊天装配的“主动活动”组件提供“候选总时限（秒）”（`proactiveTimeoutSeconds`），默认 90，允许 10–180。旧配置省略时采用默认值，替代原硬编码 30 秒；时限覆盖目标排队、资料准备、Agent 生成、平台交付及历史提交。触发票据采用同一时长，不能在 60 秒处提前失效；实际发送前仍检查当前策略、来源和目标。

总时限不会覆盖更短的模型阶段或目标发送队列时限。模型阶段默认 60 秒，来自 `tea-neko.llm.interaction.model-timeout-seconds`；目标发送队列默认 90 秒，安装表达插件时沿用 `config/agent/expression.yml` 的 `timeout-seconds`。调整候选时限时须同时核对实际较短的限制，不用模型的 `max-tokens` 推导执行秒数。

候选失败摘要包括请求 ID、最后进入的阶段、配置时限和实际耗时。超时撤销资格，迟到资料不能继续生成或发送；插件停用仍等待实际工作结束。平台已确认的结果保留，不因后续记录失败而重发。
