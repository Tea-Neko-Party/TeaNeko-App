# 共享回忆与社交组件

适用版本：v4.8.6-l。在聊天配置的 Agent 装配中启用所需组件；参数随 `components` 序列化保存到 cfg。新登记的 Agent 仍只有 LLM，已有装配也不会自动获得跨聊天读取或私聊发送能力。

## 装配与空间

| 组件 | 标识 | 依赖 | 用途 |
| --- | --- | --- | --- |
| 跨聊天回忆 | `shared-memory` | `memory` | 关联当前真实用户在同空间其他群聊中的近期对话 |
| 受控私聊 | `private-contact` | `memory`、`tool` | 用户明确邀请后，向其已启用且同空间的私聊发送一条消息 |
| 好感度 | `affinity` | `memory`、`tool` | 按实质互动积累亲近程度，影响人格表达 |
| 心情 | `mood` | `memory`、`tool` | 短期情绪变化及自然恢复，可与好感度分别装配 |
| 主动关怀 | `care` | `proactive`、`affinity` | 为原主动管道提供想念、等待回复等候选理由 |

卡片直接显示中文依赖；选择组件时依赖一起加入草稿。人格组件可按需装配，它决定表达风格；社交状态不会改写基础人格、授予工具权限或改变用户权限。

工作区的记忆空间均从已存目录选择，不支持手填创建。这里的选择用于查看资料，**不会改变聊天绑定**。需要群聊和私聊共享空间时，分别在对应聊天由 OWNER 执行 `/agent setnamespace <已有空间ID>`，再通过 `/agent status` 核对；Web 浏览与修改绑定的授权边界保持独立。

## 同一个人，不同聊天

跨聊天回忆按真实 TeaNeko 用户 UUID 关联，不按昵称猜测。来源与当前聊天须绑定同一 namespace 和 generation，且 Agent、历史读取、记忆读取仍启用。来源必须能被平台解析为群聊；私聊原文不会投影到其他聊天。

例如，用户在群聊讨论部署后再私聊，模型可以获得“来自哪个群、谁说的、何时说的”以及“当前处于私聊”的资料。只提供该用户自己的原话及与其对应的已确认助手回复，不带入其他成员的全部聊天记录。未确认的模型候选不当作已说过的话。

召回使用原消息保留期，最多检查 128 个指针、提供 24 条近期消息及约 7000 字符的资料；这不是永久完整聊天档案。短中期原接口仍按聊天隔离，长期画像仍按空间共享。切换绑定、空间换代、原文到期或回执失效后，旧资料不能继续用于发送。新消息立即建立可重建索引；旧有效消息由原维护任务逐步补建。

## 受邀私聊

模型工具 `private_message` 只接受正文和本轮邀请原文，不接受收件人、客户端或 namespace。它验证：

1. 邀请来自本轮真实用户；不能用历史、引用或工具结果充当授权。
2. 当前客户端有该用户既存映射及可确认的机器人身份。
3. 目标私聊已登记、启用 Agent，允许记忆读取，并绑定同一空间代次。
4. 发送前再次复核映射、开关、人格及空间。

不满足条件时返回具体原因，供模型按人格自然解释。每轮至多一条、最多 2000 字；沿用原发送器和持久回执，平台确认后才记录私聊历史。发送结果不明时不自动重发，也不声称成功。目标无需安装 `private-contact`；该组件授权发起聊天的能力。

## 好感度与心情

状态按“空间代次＋真实用户”保存，同一空间跨聊天共享；清空空间后重新建立。好感度与心情不是用户权限，也不是对人的客观评分。

| 组件参数 | 默认 | 范围及意义 |
| --- | --- | --- |
| `affinity.initial` | 30 | 0–100；只用于尚无关系状态的用户 |
| `affinity.positiveStep` / `negativeStep` | 2 / 3 | 各 1–5；单次变化上限 |
| `affinity.cooldownMinutes` | 60 | 15–1440；有效评估间隔 |
| `mood.decayHours` | 12 | 1–168；情绪逐渐恢复平静的时间 |

模型在原工具链中用 `social_appraise` 引用本轮连续原文，评估善意、修复、伤害或边界表达，不另开后台模型。Java 继续校验原文、普通重复问候、冷却及来源防重。重复投递、同轮多次调用不会反复加分；沉默不会自动扣好感度。心情可以通过安慰缓和，或随时间归于平静。

持久状态及来源摘要位于 `agent.social.v1`；不保存聊天正文。来源摘要保证旧消息重投后不再改变关系，不能作为一次性日志删除。旧代次的关系及来源账本由原有有界维护任务回收。

## 主动关怀

`care` 只参与已确认私聊目标的原定时候选，不另建调度器。必须装配 `proactive`、使用 ACTIVE 模式并允许定时主动活动；原静默时段、成功冷却、尝试退避、模型预算及权限继续生效。参数位置见组件卡片；主动活动的总设置见[触发说明](../../src/main/java/org/zexnocs/teanekoagent/integration/message/README.md#定时与接话配置)。

| `care` 参数 | 默认 | 意义 |
| --- | --- | --- |
| `minimumAffinity` | 70 | 达到亲近门槛才考虑关怀，范围 0–100 |
| `missingHours` | 48 | 距最近联系的小时数，范围 1–720 |
| `unansweredHours` | 6 | 已确认发言后等待回复的小时数，范围 1–168 |
| `cooldownHours` | 24 | 两次尝试间隔，范围 1–720 |
| `maxReminders` | 2 | 无新来信时最多关怀次数，范围 1–3 |

同空间且装配好感度或心情的群聊中，新一轮 Agent 互动也算联系，不会因较早私聊记录产生“很久没联系”的判断。没有达到条件时不调用模型；达到条件后仍由原人格决定问候、关心或弃言，不捏造用户遭遇。多次未回复且安装心情组件时，可以出现短期失落；不会持续追问、威胁或要求用户立即回应。

只有平台确认才累计次数；弃言或进入发送阶段前的失败保留尝试冷却，进入发送阶段后的未知结果暂停到用户再次联系。模型生成中出现新来信、目标变更或撤权会停止该候选。未回复计数持久化，重启不清零；私聊目标仍须由本进程真实入站确认，重启后不会仅凭 UUID 猜测客户端并主动发送。

## 扩展与验证

跨聊天存储通过 `ISharedConversationStore` 扩展；自定义普通记忆存储只有在使用跨聊天组件时才需提供该端口。社交状态使用 `ISocialStateStore`，平台私聊使用 `IPrivateContactTransport`，适配位于 Client 层。主动组件实现 `IProactiveContextSource`，由容器一次性组合，不能自行绕开原候选入口。

离线回归覆盖事务、重复投递、空间换代、权限撤回、发送未知和新来信取消。真实供应商的工具选择与人格表现、真实平台回执及 MySQL 并发效果仍需按[部署清单](agent-deployment.md#实机验收清单)验收。
