# 任务、定时器与日志

“任务与日志”显示 Core 运行状态及实际定时规则；4.7.1-l 起同时展示 Spring 已注册任务与声明式分类。聊天中的 Agent 持久计划在“聊天配置 → Agent 工作区 → 持久计划”管理。开启方式见[控制台部署说明](web-console.md)。

## 机器指标

概览通过独立的 `GET /api/v1/console/machine` 读取 Core 的 JDK 观测快照，需要原 HTTPS 管理会话。此入口不开放 Actuator、主机名、文件路径或其他进程信息。

| 指标 | 含义 |
| --- | --- |
| 系统 CPU | JDK 最近统计窗口的负载百分比 |
| 程序 CPU | 当前进程两次采样间的 CPU 时间，按经过时间及 JVM 可用处理器数归一化 |
| 物理内存 | 当前运行环境可见的已用量和总量，不包含交换空间 |
| JVM 堆 | 已用、已提交和上限分别展示，未定义的上限保留为空 |
| JVM 非堆 | 独立展示已用和已提交量 |
| 进程常驻物理内存 | 当前 JDK 管理接口未提供，明确显示不可用 |
| 程序所在磁盘 | 工作目录所在卷的已用、总量和当前进程可用空间；不汇总其他磁盘，也不代表程序文件自身大小 |

采样最短间隔一秒，多个页面可复用同一快照，以响应内的采样时间为准。首次 CPU 只建立基准，不显示为零；不支持或无效的数据保持为空。页面可见时在上一请求完成五秒后刷新，不重叠请求、不积累历史曲线；隐藏、离开概览、退出及销毁会取消读取和后续刷新，恢复可见时立即读取。失败保留上次快照并提示时间，不冒充新采样。

JVM 运行时长从当前 JVM 启动计时，开发热重启不会重置。已提交虚拟内存及堆上限不能代表常驻物理占用；CPU 和内存的可见范围受运行环境及 JVM 支持限制。

磁盘已用量按总量减空闲量计算；当前进程可用量可能因文件系统保留空间或权限而更少。容量不可读时显示“暂不可用”，满盘的可用量则正常显示为零。

## 定时规则

目录读取原 TimerService 与 Spring `ScheduledTaskHolder` 实际持有的任务，不创建另一套调度器。展示中文任务名、分类、来源、说明、规则及可确认的下次触发时间。自定义规则或框架没有提供时间时显示未知。

点击分类标签，或按规则类型、运行状态和名称筛选。服务端在分页前执行过滤，切换条件从首页开始；分类标签来自完整观测窗口，不会因为当前页没有匹配项而消失。目录最多观测 4096 项，超出时明确提示。

当前分类包含 Core 维护、Agent 记忆、Agent 主动活动、Agent 计划任务、Agent 素材、客户端维护和业务插件；旧插件没有声明时为“未分类”。分类来自 `@TimerDisplay` 或注册端明确提供的元数据，不根据任务名称猜测。

4.7.3-l 为项目内 15 个定时来源补充详细介绍，覆盖执行对象、触发后的工作、是否调用模型或向真实聊天发送，以及暂停或只读的边界。介绍随原任务声明提供并直接显示在卡片中；实际周期、预计触发时间和运行结果仍以调度器观测为准，增加介绍不改变调度与权限。

- FixedRate：根据原触发时间加固定间隔估计，不等待上次完成。
- FixedDelay：上个原任务完成后开始等待；等待完成期间不承诺下一次时间。
- SmartRate：同时要求间隔已到、上次原任务已完成。
- Core Cron：使用原表达式与 Asia/Shanghai 规则，显示实际计算的下次时间。
- Spring：使用框架实际解析的间隔或表达式与公开的预计时间；运行状态只描述原调度方法，方法发起的异步模型、发送或事务可能仍未结束。框架没有公开的时区和暂停事实不作推断。

可管理 Core Timer 的“暂停”和“恢复”与原调度循环共用门禁，动作要求原版本。网页暂停不修改原 IPausable/ILivable，不覆盖来源自身的暂停。恢复过期规则后是否立即触发由原计时器决定，不另造补跑策略。已有任务继续执行。

Spring 来源始终只读。调度循环、缓存/历史/记忆回收、Agent 扫描及其他关键维护也声明为只读，服务端同样拒绝伪造暂停请求。单条 Agent 持久计划继续在聊天工作区操作，不能通过暂停整个派发循环代替。未注解的旧 Core 任务保留原门禁能力。

网页门禁只在本进程保留，重启后复位。操作 UUID 与原参数绑定，回执保留一天、最多 256 项；中断后可查询原编号或原样重试，版本冲突不自动覆盖。历史回执不证明当前门禁仍是原值。目录观测上限为 4096 项，到达上限明确提示；原调度本身不因观测容量满而停止。

## Core 任务

任务窗口展示原 Task 注册、排队、实际同步阶段、等待外部结果和最终原回执。方法返回空值表示等待原外部提交，不能直接显示成功；重试仍关联同一个任务 UUID。

**Core Task 回执与外层业务 Stage 分开。** 例如指令提交任务已经完成，模型、工具和消息发送可能仍在继续，业务终态应查看 Agent 活动时间线。窗口不输出任务参数、返回值或异常链；不提供无法确认物理停止的通用强制取消，也不编造进度百分比。

窗口是单进程内存观测，默认最多 1000 项、60 分钟，容量淘汰和重启均明确显示。较早页不自动刷新；自动刷新只在页面可见且当前分区活动时每五秒执行。原任务不因观测淘汰而取消。

## Agent 持久计划

计划来自 Agent 专用 EasyData 原任务域，按已解析的真实聊天过滤。分页扫描最多一百条原记录，空匹配页仍可能有后页；“继续扫描计划”沿原扫描游标读取，不把空页当作全库为空。

显示原标题、动作、状态、发生时间、时区、间隔、版本及最近安全结果；不返回动作参数和创建者权限。ACTIVE、RUNNING、PAUSED 可取消未来计划；COMPLETED、CANCELLED、EXPIRED、INDETERMINATE 保留原语义，不提供无条件重试或臆造暂停恢复动作。

管理取消使用独立管理来源，不构造原生用户。真实聊天、版本、当前授权和幂等回执与计划变更在同一原事务提交；原生执行器的认领与后续守卫继续生效。回执在原任务域 management 数据中持久保留一天、最多 256 项。重放不会重复变更，其他聊天或主体不能借操作编号读取。

取消只阻止未来动作，已经开始的外部动作可能完成。RUNNING 代表已认领执行权；取消时不会把已经发生的发送声称为撤销。创建新计划仍走已有原生指令或工具，本批没有开放网页伪造用户创建计划。

## 日志采集与筛选

应用就绪后采集实际 Logback 事件，支持等级、来源、时间、正文、结构化请求号、聊天标识和插件筛选。后面三项只在来源通过 MDC 提供 requestId、scope、plugin 时可用，不从正文猜测关联。默认 ILogger 的实际命名空间单独提取，第三方日志使用真实 logger 名称。

默认只记录等级、来源和结构化标识，不格式化或保存正文、参数数组及异常链。需要正文时由本机管理员编辑并按原流程重载：

```yaml
# config/runtime/observability.yml
max-runs: 1000
max-logs: 2000
retention-minutes: 60
capture-messages: false
```

max-runs 范围为 100–10000；max-logs 为 100–20000；retention-minutes 为 5–1440。配置不可用时使用有界默认策略并关闭正文采集。关闭正文只影响后续采集，先前已采集的条目仍按保留策略淘汰。

明确改为 capture-messages=true 后，正文最多 2048 字符，隐藏常见认证字段、URL 和长令牌；**无法保证识别业务自行输出的任意裸秘密或私密原话**。应先修正产生日志的业务，不把脱敏当作允许打印密钥的理由。页面按文本渲染，不执行日志中的 HTML。

日志窗口默认最多 2000 条、60 分钟；内存锁繁忙时丢弃新日志，不阻塞业务。筛选按实际扫描游标推进，没有匹配结果仍推进，避免重读同一页。旧游标过期或进程换代会提示；浏览器最多保留最近读取的 300 条。修改筛选后点击“应用日志筛选”重新扫描。

这是当前进程日志窗口，**没有开放磁盘日志、历史文件下载、跨重启历史或完整启动日志**。长期留存继续由部署侧日志系统负责，不将内存窗口冒充持久日志档案。

## 记忆整理失败诊断

启动约五秒后，分层记忆会检查数据库中的未完成整理任务，即使没有新聊天也可能工作。失败保留原记录与整理进度，仍使用既有租约和退避重试。

警告现在包含请求 UUID、租约批次、实际处理阶段、稳定原因、模型状态、准入/就绪状态和安全异常位置。例如 `MODEL_RESULT` 配合 `TIMED_OUT` 表示模型未及时完成，`INVALID_OUTPUT` 表示模型 JSON 不符合记忆协议；`ACCESS_REVOKED` 配合 `READINESS_UNAVAILABLE/MODEL_UNAVAILABLE` 表示模型配置未就绪，`LEASE_CHANGED` 表示原输入或租约变化。`EXECUTION_DEADLINE_EXCEEDED` 表示整批处理超过时限。

模型请求号与 LLM 交互日志相同，HTTP 401 等传输错误可通过该编号关联。只记录原因、状态和异常类型，不打印原对话、模型原文、凭据或任意异常消息。持续相同失败时据原因检查开关、模型配置、凭据、预算或存储；不能仅靠重启消除问题。

网页可按来源“Agent 分层记忆”或“Agent 长期记忆”和结构化请求号筛选；要在网页按原因或阶段搜索正文，须启用上述 `capture-messages`。后台控制台仍可直接读取这些诊断。

## 扩展与安全

Core 运行与日志分别贡献 `teaneko.core:runtime`、`teaneko.core:logs`；聊天计划贡献 `teaneko.agent:schedules`。三项均须列入本机 management-resources；旧配置文件不会因模板升级自动增加白名单，需本机明确补充后重载并重新登录。

全局资源实现 GlobalManagementResource，经 `POST /api/v1/management/{resource}` 进入原 ManagementGateway；聊天入口不能调用全局资源，全局入口也不能拿聊天资源冒充全局能力。沿用真实会话、CSRF、插件代次及在途上下文授权，没有平行匿名管理网关。请求与真实完成阶段结束后才释放控制和并发槽。

自定义 ITimer 可覆盖 observation() 返回 TimerObservation；仅提供实际可知的规则与时间，不联网、不触发任务。其他实例级管理贡献实现 GlobalManagementResource 并注册 Spring Bean，宿主继续按本机白名单决定是否开放。日志插件通过结构化 MDC 补充关联字段，不把控制对象或凭据写入日志。

必要测试使用真实本地执行器、计时器、原 EasyData 事务夹具与真实 MVC 安全链；页面另外使用离线 API 夹具。真实数据库、调度负载、日志后端重配置和公网部署仍需按部署清单实机验证。
