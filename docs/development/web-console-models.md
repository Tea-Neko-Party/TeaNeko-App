# 模型配置

v4.8.0-l 的聊天模型选择位于“聊天设置 → 组件装配 → 大语言模型”。系统模型继续使用本页流程；聊天私有模型直接保存到专用 cfg 数据库，不写文件，见[Agent 组件装配](agent-composition.md#聊天私有模型)。

v4.7.5-l 起，“模型配置”独立于普通本地配置，属于系统内置功能。入口需登录管理员会话，默认开放；仅启用 `local-allowlist-enabled` 时才要求 `file-sections` 包含 `agent.models`。业务插件开关及插件总管理权限不控制该入口。沿用原 `model.yml`，没有新增凭据文件。

## 添加和调整

1. 点击模型目录右侧“＋”，在弹窗内选择 DeepSeek、Kimi、OpenAI 或 Antigravity 类型，再填写新模型；类型不会直接展开在主页面。地址及接口路径由供应商适配器填写。具体模型默认从列表选择；需要自定义名称时打开“手动输入”。已保存模型也使用相同控件，旧名称不会被列表更新覆盖。选择已知型号时同步其真实上下文容量，手动填写时需自行核对。
2. API 密钥选择“手动填写”并输入新密钥，或选择“环境变量”只填写变量名，如 `DEEPSEEK_API_KEY`；后者保存为 `${DEEPSEEK_API_KEY}`，保存校验及应用时由 Core 统一解析。变量必须在后端进程环境中存在，网页不会读取或显示变量值。刚在系统中设置变量时，已启动的 IDE/后端不会自动继承：可在运行配置中显式设置，或重启 IDE 和后端。缺少变量时页面显示变量名和处理办法，不覆盖原文件；修正后可继续编辑保存。
3. 可勾选设为默认模型，点击“保存模型”立即写入文件。自 v4.9.1-l 起，模型页在保存成功后自动应用该保存回执对应的磁盘版本。编辑、删除和“保存并应用”同样接续应用；应用失败明确提示磁盘已保存、运行尚未确认。“应用磁盘配置”保留为外部编辑或应用失败后的恢复入口。保存前提示 YAML 将重新排版且不保留注释。普通本地配置页面仍分别保存和应用。
4. 模型卡片显示路由、型号、默认标记、输出/上下文额度及检测状态。弹窗先显示协议适配器、服务地址、接口路径，再显示路由标识与其余参数；型号和手动开关同行，高级模式展示 metadata 等扩展参数。已有 API 密钥仍不回显，动作使用“替换密钥 / 清除密钥”。明确的参数校验失败可直接修正草稿，网络中断等结果未知的失败仍保留原操作供查询。

样板可先以空密钥保存，实际调用前须配置有效凭据。预检和应用确认不调用远端，也不证明供应商授权、余额或模型能力可用。v4.7.7-l 起同一协议可添加多个配置，`id` 是唯一配置路由，`adapter` 是实际协议；例如 `id: deepseek-chat`、`adapter: deepseek`。每条路由独立保存型号、密钥和连接，重复 `id` 被拒绝。旧文件省略 `adapter` 时沿用同名协议，一次编辑允许一个结构增删动作，保存后可继续添加或编辑。

模型图标随程序从本地资源加载：DeepSeek 使用无文字的鲸鱼图标，Kimi、OpenAI 与 Antigravity 使用各自官方图标。品牌名称和标志属于对应供应商，仅用于识别所选服务。[DeepSeek](https://api-docs.deepseek.com/)、[Kimi](https://www.kimi.com/resources/kimi-brand)、[OpenAI](https://openai.com/brand/)、[Antigravity 图标来源](https://antigravity.google/favicon.svg)。

## 切换聊天模型

先在“模型配置”添加路由并等待应用确认，再进入该聊天的“聊天设置 → 组件装配 → 大语言模型”选择模型路由；空值继承文件默认。这个字段也在网页房间内的聊天设置子页显示。

v4.9.1-l 起，模型卡片将默认路由排首位；LLM 选择器先列“继承默认模型”，随后列具体默认路由及其他路由。默认路由变化后，继承选择从新请求开始使用新的默认模型；已显式选择路由或聊天私有模型不被改写。保存应用完成、重新打开参数弹窗及弹窗内前台轮询会更新模型目录，保留未保存的聊天装配草稿。其他会话的变更在弹窗重新聚焦或下一次轮询时同步。

命令 `/agent models` 列出已经应用的路由；OWNER 可使用 `/agent model deepseek-chat` 切换当前聊天，或 `/agent model default` 恢复继承。模型选择与其他聊天配置共用原版本事务；切换从新请求生效，正在执行的旧策略会在后续复核时停止，不自动重发。私聊和群聊继续沿用原配置共享规则。

“自定义模型”选择已注册的协议适配器，自行填写模型名、服务基础地址和相对接口路径；已有模型的编辑弹窗也直接显示地址和路径。自定义连接须符合所选适配器的协议，不会动态加载新 Java 实现。

### Gemini 原生代理

选择“Antigravity（Gemini 原生）”时，`adapter` 为 `antigravity`，可保留原路由 ID，例如 `gemini`。基础地址不带 `/v1`；接口填写集合路径 `/v1beta/models`，分组网关需要专用入口时填写 `/antigravity/v1beta/models`。模型名和生成动作由适配器追加。默认以 SSE 接收并交付完整回答；代理不支持时可在该模型条目设置 `stream: false`。密钥分组是服务端调度规则，不等于应用请求协议；普通入口拒绝分组时先核对专用路径。

该协议通过 `generationConfig.responseJsonSchema` 发送结构约束，支持用户图片和工具续轮。旧 Responses 适配器继续可用；可用不同路由 ID 同时保存两种连接，不自动换协议。新代码需重启加载，之后按原流程保存应用配置。连接、图片声明、思考参数和能力边界见[原生协议说明](../../src/main/java/org/zexnocs/teanekoagent/llm/instance/antigravity/README.md)。

输出额度统一使用此处的 `max-tokens`。上下文容量必须对应实际模型；输入默认最多占 80%，且仍为完整输出预留空间。切换模型时须同步核对容量，不能只更换名称。样板容量依据对应供应商资料：[DeepSeek](https://api-docs.deepseek.com/api/list-models/)、[Kimi](https://platform.kimi.ai/docs/guide/kimi-k2-6-quickstart)、[OpenAI](https://developers.openai.com/api/docs/models/gpt-5.5)。

“Agent 用量告警”的阈值来自独立的 `tea-neko.agent.monitor.alert-tokens`，累计一轮内多次调用的输入及输出，仅用于提醒，不覆盖模型 `max-tokens`。参数来源及冷却见[轮次监控](../../src/main/java/org/zexnocs/teanekoagent/runtime/monitor/README.md)。

## 检测已保存模型

模型卡片初始显示“未检测”，打开编辑或保存新文件版本后原检测失效。点击“检测模型”按已保存的文件快照进行一次真实文本调用，不应用磁盘配置，也不使用旧运行缓存冒充检测。返回完整非空回答才显示成功，并明确提示这是无工具短文本检测；失败显示安全原因，如 HTTP 401 认证失败、403 权限限制、404 地址/路径/型号不存在、429 限额、网络超时，未知错误显示代码位置。

检测会产生供应商调用费用；每次最多 60 秒、实例最多四个并发，沿用模型自身 `max-tokens`，不额外压低额度。检测结束后释放临时凭据来源；文件版本或管理员权限变化后拒绝迟到结果。状态仅保存在当前页面，不持久保存凭据或供应商响应。检测成功不代表工具、图像等所有能力均通过验收。

入口为 POST `/api/v1/model-configurations/{id}/probe?revision=文件版本`，继续要求管理员会话、CSRF 和原文件配置区权限。插件额外提供的模型协议仍须满足该扩展自身的启用条件。

### 连接中断的定位

`SocketException` 或响应提前关闭会显示“请求传输中断，未取得完整响应；远端处理结果未知”，与连接建立失败、HTTP 拒绝和数据解析错误区分。此时不能依据供应商控制台的一次成功就判定当前请求已经被应用接收，也不能假定上游没有执行或计费。先用请求 ID 对照同一条交互的诊断记录，再核对该时间段的网络及上游网关日志；相邻请求成功不能替代失败请求的响应证据。

连接检测只请求一条短文本且不声明工具。短文本成功、复杂工具合成检查成功，均不能证明原聊天长时执行及完整工具续轮已经通过。2026/11/10 的实际调查范围与待核实项见[模型连接中断调查](../review/4.9.0-l/model-transport.md)。

## 图片输入与表情包独立模型

v4.9.1-l 的模型条目支持可选 `image-input`：省略按协议已维护型号判断；`true` 明确允许兼容视觉型号，`false` 禁止图片输入。Responses 保持 `input_image`、`image_url` 与 `detail` 映射，支持内联图片；声明不会作为额外 API 字段发送。具体远端服务是否识图须实际检测。

日志显示“当前模型未声明图片输入能力”时，先核对当前聊天所选模型的图片输入设置；自定义兼容视觉型号需要明确允许并保存应用。图片校验报告同时包含失败字段位置、允许的角色/细节和实际值；具体格式见[LLM 输入契约](../../src/main/java/org/zexnocs/teanekoagent/llm/framework/README.md)。`AUTOMATIC_REPLY` 使用聊天 LLM，表情包独立视觉模型只用于采集，不会替换自动回复的模型。一次识图检测的临时试送成功也不会自动修改模型图片声明。

表情包组件可独立选择已记录路由或填写私有模型，默认完整跟随聊天 LLM。插件配置中的“表情包识图模型”设置全局备用；组件与全局页均提供检测按钮，只发送打包的合成低分辨率图片，不携带聊天、工具或图库数据。检测只校验本处选择，不用备用成功覆盖首选失败。完整参数、旧字段兼容、备用计费与次数边界见[图库说明](../../src/main/java/org/zexnocs/teanekoplugin/agent/expression/sticker/README.md#独立识图模型与检测)。

## 扩展入口

### 维护的型号列表

截至 2026/11/04，页面手动维护以下选项，不启动供应商模型列表请求：

- DeepSeek：`deepseek-flash`、`deepseek-v4-pro`，上下文均为 1,048,576 tokens。[官方型号说明](https://api-docs.deepseek.com/quick_start/pricing/)
- Kimi：`kimi-k3.1-pro`、`kimi-k3.1-pro-highspeed`、`kimi-k3`（1,048,576 tokens），以及 `kimi-k2.7-code`、`kimi-k2.7-code-highspeed`、`kimi-k2.6`（262,144 tokens）。K2 系列对新注册账号的开放范围受供应商限制，已有配置不自动迁移。[官方模型列表](https://platform.kimi.com/docs/models)、[容量与开放范围](https://platform.kimi.com/docs/pricing/chat)

后续型号变化由维护者更新供应商目录中的 `models` 和 `contextWindows`，随补丁发布；网页可通过手动输入开关立即填写新的兼容型号。列表声明和保存成功不证明当前 API key 对该型号具有调用权限。

供应商目录中的 `@LLMConfigurationAdapter(id = "实际协议标识", icon = "/console/models/图标文件")` Spring Bean 实现 `ILLMConfigurationAdapter`，返回公开名称、说明、默认参数及模型名建议；固定地址和路径复用同目录适配器常量。图标是可选的同源资源，未声明时显示名称缩写；新增适配器不需要修改前端供应商判断。只有模型服务中实际注册且插件启用的协议进入目录，重复标识和声明不一致明确报错。

新增凭据输入方式使用 `@LLMCredentialInput(id = "唯一标识")` 并实现 `ILLMCredentialInput`，提供显示文本、掩码、正则及前后缀编码。页面自动发现并构造原文件可接受的字符串；扩展输入方式不会自动为后端增加新的凭据解析协议。完整职责见[插件指南](plugins/management.md#网页房间与模型配置扩展)。

目录接口 GET `/api/v1/model-configurations` 只返回公开样板，不读出配置凭据。实际预检、保存、应用及回执继续使用 `/api/v1/file-configs/agent.models` 下的原接口、文件版本和操作编号。模型网页自动接续两个独立事务，不将磁盘保存伪装成应用成功；未确认操作先查询原编号，确认原保存成功后才接续一次应用，版本冲突或应用失败不盲目重试。详细事务及权限见[文件管理](web-console-files.md)。
