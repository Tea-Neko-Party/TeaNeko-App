# Agent 组件装配

适用版本：v4.8.0-l。

## 默认行为与使用

`/cfg reg agent` 只安装必要的 `llm`。它能对话，但不会保存会话上下文、采集记忆、加载人格或调用工具。网页私聊首次登记也使用这一默认值；总开关、模型就绪和聊天权限仍须满足。

已有记录未包含 `components` 时继续使用原开关、参数和默认能力，不在读取时迁移或写回。Web 显示等价的内置组件预览；只有保存装配后才采用新协议。只修改聊天开关不会转换旧配置。

在“聊天配置 → Agent 配置”选择聊天；网页聊天室也可在自己的“聊天设置”子页操作：

1. 打开所需组件，点击“参数设置”修改独立参数。
2. 依赖组件一起加入草稿；卸载依赖前须先卸载使用它的组件。LLM 不可卸载。
3. 保存后通过原配置事务提交并重新读取。版本冲突不会自动覆盖。

高级模式提供脱敏 JSON 预览。草稿只保存在当前页面内存，不写浏览器长期存储。

| 标识 | 功能 | 必需依赖 |
| --- | --- | --- |
| `llm` | 系统模型或聊天私有模型，所有装配必需 | 无 |
| `memory` | 会话上下文、持久历史、摘要、分层记忆与画像 | 无 |
| `personality` | 身份、说话风格及补正 | 无 |
| `tool` | 工具选择及名称限制，命令工具另有开关 | 无 |
| `skill` | 选择本地已注册技能，保持原目录和工具权限 | `tool` |
| `expression` | 分段协议、发送节奏及原生表情 | 无 |
| `sticker` | 表情采集与共享图库回复 | `expression`、`tool` |
| `schedule` | 自然语言提醒与定时任务 | `tool` |
| `proactive` | ACTIVE 模式下的主动候选、静默和冷却 | 无 |

安装组件不绕过本地功能开关、客户端范围、权限、预算或插件启停。人格可单独安装；自动观察仍需真实对话证据，通常与记忆配合。未安装人格的记忆使用独立的无人格分区，不自动创建人格记录。

卸载组件不删除已有数据。卸下记忆后不继续采集或使用上下文；旧任务执行时重新检查当前装配。namespace 共享、人格按聊天独立的规则保持不变，资料查看和清理仍走专用管理入口。

## 命令配置

`components` 是完整的版本化 JSON 文本字段，命令一次替换整个装配：

```text
/cfg set agent components {"version":1,"components":{"llm":{"source":"system","route":""}}}
/cfg set agent components {"version":1,"components":{"llm":{"source":"system","route":"deepseek-chat"},"memory":{"historyMaxMessages":24},"personality":{},"tool":{}}}
```

`version` 目前为 `1`；空参数对象使用组件自身默认值。最多 32 个组件，文本最多 131072 字符；重复键、尾随内容、未知组件、缺失依赖与越界参数都会拒绝。具体字段以“API 文档 → 组件与系统”实际目录为准。

显式装配后，旧 `historyMaxMessages` 等平铺字段不再控制对应组件。`/agent models`、`/agent model <路由>` 和 `/agent model default` 仍可使用，只替换 LLM 选择，保留其他组件。切回系统模型时移除原私有连接配置。

## 聊天私有模型

LLM 参数选择“当前聊天私有模型”，从已注册协议样板填入型号、连接、输出额度和真实上下文容量，也可手动修改地址及路径。凭据支持手动填写与后端环境变量。形状与 `model.yml` 单条模型一致，但保存到当前聊天的 Agent 专用 cfg 行，不写模型文件，不需要执行文件配置的“应用”。

```json
{
  "version": 1,
  "components": {
    "llm": {
      "source": "custom",
      "configuration": {
        "adapter": "deepseek",
        "model": "填写供应商实际型号",
        "base-url": "https://api.deepseek.com",
        "api-path": "/chat/completions",
        "api-key": "${CHAT_MODEL_API_KEY}",
        "max-tokens": 2048,
        "context-window-tokens": 8192,
        "context-input-ratio": 0.8,
        "metadata": {}
      }
    }
  }
}
```

示例容量仅说明格式，实际值以部署型号为准。`adapter` 必须显式填写，不会注册新协议。保存前检查必需环境变量及参数；成功不表示远端凭据、余额或型号可用。

密钥不回显。修改其他参数时 Web 明确保留原密钥，点击“替换密钥”才替换；保留标记不能复制到 `/cfg` 当作密钥使用。环境模板由 Core 解析，不回写展开值。`configuration` 整体不进入公共 ECS 快照，实际连接只在认证边界读取。私有路由绑定装配摘要，关闭、注销或修改配置会拒绝旧轮次。合法私有模型不依赖系统 `model.yml` 是否可用。

数据库备份仍包含受保护配置。不要把明文密钥发到群聊；命令中使用环境占位符，或通过管理员 Web 表单设置。同一 TeaNeko UUID 共用配置键的私聊仍共享此配置，并非每个客户端独立。

## API 文档

侧栏提供指令一览、组件与系统、工具目录，数据来自注册声明，只允许管理员读取，不请求模型。组件页说明字段、依赖、系统阶段及读写键；工具页提供注解工具参数与客户端范围。动态工具仍按实际轮次、资料和业务条件选择，目录不是调用授权。

组件默认按 LLM、工具、记忆、人格、表达、表情包、Skill、计划、自主发言排列；扩展通过 `@TeaNekoAgentComponent.order` 指定顺序，越小越靠前，未指定为 1000。排序和描述在初始化/显式重扫时缓存，参数及插件启用状态仍实时检查。卡片独立高度，字段与系统信息分层显示。

工具目录允许参数 schema 省略空的 `required` 或 `properties`；空可选参数不再导致整个目录渲染失败。

扩展见[可装配组件开发](plugins/agent-components.md)及[Agent 插件](plugins/agent.md)。
