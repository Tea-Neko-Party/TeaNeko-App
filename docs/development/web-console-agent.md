# Agent 网页工作区

适用版本：4.9.0-l。先按[控制台部署说明](web-console.md)启用 HTTPS 与管理会话，然后直接进入“Agent 工作区”，在独立目录选择平台、机器人账号和聊天。该选择与“聊天配置”分别保留，点击左侧返回图标回到本页目录，不再跳转配置页；有草稿或未确认操作时仍先确认是否切换。从聊天配置或网页聊天的“活动与记忆”入口也可进入工作区。实际目标继续由服务端解析，不接受浏览器拼接 scope 或提交原生用户身份。

## 独立空间

Agent 工作区上方可切换“聊天工作区”“记忆空间”“人格空间”。独立目录自动读取后续页并支持搜索，不因查看而注册 Agent、创建空间或改变聊天绑定。记忆空间输入统一改为可搜索的已存空间下拉框，不接受任意文本创建空间。

- 记忆空间：按“用户画像”“共享事件”“空间维护”分区。个人事实和偏好只在画像中展示，共享事件显示没有个人主体的长期条目；短中期与整理作业仍在具体聊天查看。
- 人格空间：包含普通补正和只读备份。新增补正先选择本地基础人格；编辑按原基础身份校验。基础定义已失效的旧补正仍可撤销或克隆保存，不能改成另一种人格。
- 用户画像：首次进入及刷新直接读取本空间全部用户目录，自动越过空分页。展示已有客户端映射和昵称，未知时显示 UUID；点击后在同一区域进入独立详情页，左侧返回列表，不再把详情堆在列表下方。不会为查看自动创建用户。

空间编辑继续使用原事务、版本、备份与操作回执。独立空间没有聊天绑定版本，不能借此给任何聊天切换绑定。左侧返回会检查草稿及未确认操作。

升级已有配置时，旧管理资源 ID 按[精确授权迁移规则](plugins/management.md)转换，不扩大已有权限。当前 `config/web/security.yml` 的 `management-resources` 使用下列 ID；新增授权需部署者明确配置。修改后重载文件配置或重启后端，并重新登录。

| 页面能力 | 所需资源完整 ID |
| --- | --- |
| 空间和画像目录 | `teaneko.agent:library` |
| 独立记忆空间、用户画像 | `agent.cognition:memory-space`、`agent.cognition:layers-space`、`agent.cognition:profile-space` |
| 独立人格空间 | `agent.cognition:personality-space` |
| 聊天工作区 | `teaneko.agent:activity`、`agent.cognition:memory`、`agent.cognition:profiles`、`agent.cognition:personality`、`agent.cognition:layers`、`agent.automation:schedules` |

关闭 `agent.cognition` 或 `agent.automation` 后，其工作区分区和操作入口隐藏；原数据保留，可在插件总管理重新开启。

任务与日志另需 `teaneko.core:runtime`、`teaneko.core:logs`。这些是当前页面实际调用的全部管理资源；不需要开放通配符或额外 Controller。

## INFO 观测

每条请求链结束时只输出一份汇总。Agent 负责自己的汇总，内部 LLM 不重复输出；后台记忆整理等独立交互由 LLM 汇总。4.8.6-l 默认使用 INFO，以文字分组展示统计摘要、本轮用户输入和最终回复；可切换 DEBUG 或关闭。错误仍按实际原因报告，网页时间线保留阶段记录。

前置拒绝、配置错误和服务关闭后的有效请求也会汇总，未调用模型时次数为零。一次执行只通知一次；没有形成有效请求的调用参数错误不伪造请求编号。

在本地配置“Agent 观测日志”保存后应用，或编辑 `config/agent/observability.yml` 后重载。下次汇总使用新配置。

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `agent-info` | `true` | Agent 请求汇总；关闭后其内部 LLM 也不单独输出 |
| `llm-info` | `true` | 独立 LLM 交互汇总 |
| `visibility` | `INFO` | `INFO`、`DEBUG`、`NONE`；DEBUG 还受日志框架级别控制，NONE 不影响业务错误报告 |
| `include-context` | `true` | 下列输入、回复、系统、结构和工具项的正文总开关 |
| `include-user` | `true` | 首次调用中的当前用户消息，仅一次 |
| `include-final-output` | `true` | 本轮最终模型回复，不重复历史助手对话 |
| `include-system` | `false` | 去重后的系统指令，结构说明另行控制 |
| `include-schema` | `false` | 去重后的输出 Schema 和工具定义；不会因工具续轮重复打印 |
| `include-tools` | `false` | 每个工具调用的参数、状态和结果，各一次 |
| `include-reasoning` | `false` | 供应商实际返回的明文推理或摘要，独立于正文总开关 |
| `max-content-characters` | `16384` | 单条汇总正文上限，范围 1024–2000000；超限明确标注 |

状态、耗时、模型/工具次数及本次全部尝试的 token 总量始终保留。已报告、估算、未知用量分开统计，不重复累加父执行预算。图片只显示占位；授权凭据、常见密钥字段、链接和内联二进制不原样记录，也不导出加密推理状态。正文仍可能包含聊天隐私，关闭 `include-context`、`include-reasoning` 可只保留统计。

日志使用稳定标题和缩进分组，不把整条记录编码成 JSON。模型原文若本身是 JSON，保持其原文用于诊断。旧配置中显式开启的推理等选项继续有效；升级时若希望采用精简值，将对应开关改为上表默认值后应用。

脱敏先处理完整字段，再执行显示截断。JSON 按键隐藏完整敏感值，并检查最多 4 层编码；授权头包含分号后值及缩进续行。单字段最多处理 200 万字符，单条汇总累计最多 800 万字符和 4 万节点；JSON 结构深度上限为 32。无法可靠处理的编码、畸形敏感片段或超限内容显示隐藏标记，普通字段继续保留。这些限制仅作用于观测，不改变模型输入或业务结果。

输入快照只跟随本次执行结果，不进入活动时间线或数据库。汇总表示 Agent/LLM 本轮结束，平台是否发送成功以交付回执为准。直接模型检测等未走交互服务的调用不在此汇总范围。

## 活动时间线

记录冷轮次登记、实际启动、准入、上下文准备、模型与工具交互、结果/历史处理、已安装的插件阶段，以及模型终态。逐段发送由原 AgentDeliveryService 在实际传输回调和完成处记录，模型成功不等于平台已经发送；交付失败保守显示结果不确定。阶段“返回”仅表示该步骤的异步操作返回，不额外证明后续提交或平台交付完成。

当前模型请求、工具结果和 token 统计来自原脱敏轮次报告，没有展开逐次工具参数、结果正文或隐藏推理。报告用量、估算用量和未知用量分别显示，不冒充精确费用。当前没有通用排队、后台学习逐步骤或全部插件内部节点的埋点，不根据时间线缺项推断操作没有发生。

全进程窗口至多保存 4096 个节点，按当前目标过滤，每页至多 100 项；页面保留最近 300 个节点和 15 组请求。窗口 ID、开始时间、游标失效与截断均明确返回，重启不保留此窗口历史。没有节点时显示真实空状态。

活动页可每十秒自动刷新；页面隐藏、切换分区、操作未结束或存在待确认操作/草稿时停止自动读取。当前使用有界 HTTP 增量查询，尚未提供 SSE 或持久活动账本。

## 短中长期记忆

“短中长期记忆”读取原持久化存储，不调用模型、不触发压缩或学习，也不自动初始化空间。短期显示当前聊天实际引用分区最近 24 条有效消息，单条最多展示 4096 码点，省略和处理时间估算分别标注。助手存档表示生成记录，实际发出与否查看交付节点。

中期显示原保留策略下最近 6 份摘要，保留简述、详情和原消息时间区间。长期读取原自动整理与明确保存记录，按 namespace 共享；网页从用户目录查看个人事实与偏好，或按字面话题查询共享事件，每次最多返回 20 项，原索引候选扫描不超过 256 项。事件在截断前独立筛选，不被大量个人条目挤出。有限召回不代表全量目录，页面显示扫描与限制状态。

长期条目可按已读版本修正或遗忘。修正保留人工保护；遗忘保存墓碑及原证据抑制，不删除原聊天、不允许旧片段普通整理自动复活。独立管理员不会冒充条目主体 UUID，本人聊天维护入口仍校验真实主体。与既有领域规则一致，查询只展示有效或明确分歧的条目，已遗忘条目不会重新出现在普通召回。

原“记忆证据”实际是一套独立事实库，并非自动长期记忆的证据总表；现改名“独立事实”，放在“空间维护”中。通过原事实接口保存的资料仍可用于事实查询和画像投影，保留主体、来源、时间精度及锁定，支持按 revision 修正、锁定和解锁。当前自动学习与明确保存主要进入长期库，因此这里为空并不表示 Agent 没有记忆。

长期记忆自身的证据承担逐字引用、作者、来源 ID 和重复学习校验，仍由后端保留；不把它们重复复制到“独立事实”。原证据克隆仅复制独立事实的完整有界快照，不复制自动长期条目、中期摘要、短期消息、人格或聊天绑定，不是完整三层记忆备份。

“清空共享空间”复用权威 generation 换代，影响所有引用此 namespace 的聊天和三层读取，保留人格及其他空间。提交后协调原共享会话；协调失败会明确说明已提交，不能据此重复发起新操作。旧数据物理回收继续使用原维护/清理入口，不将逻辑换代称为全部物理删除。

## 画像与人格

画像按真实 TeaNeko UUID 查询，分别展示原事实/偏好证据和自动长期画像条目，保留各自扫描限制。两个来源必须观察同一 namespace/generation，否则要求重读；不承诺跨来源的完整事务快照。原事实投影预算为最多 30 条、16000 字符、300 个候选；长期部分沿原召回预算。修正或遗忘对应证据后，后续画像重新构建，不维护第二份可任意覆盖的画像结论。

“长期记忆”和“用户画像”此前会显示同一条长期记录，现在按主体分区展示，未删除已有数据。跨聊天回忆、受控私聊和可装配的关系、心情、主动关怀见[社交组件说明](agent-social-memory.md)。

人格页面展示本地有效基础人格、允许补正的表达字段、当前聊天绑定、内容版本及最近备份引用。基础内容仍由本地配置管理；普通网页补正不能改身份、工具权限或用户事实。基础配置须有效，首次正常 Agent 交互前没有绑定时明确提示，不因查看而创建绑定。

当前绑定的非备份补正支持新增、编辑、锁定/解锁和撤销；支持创建不可变备份、克隆并显式绑定已查看的可写 key。共享同一 key 的聊天会受影响；克隆/备份不自动改变绑定或清空会话。每次写入固定原绑定版本及内容版本，基础配置变化时也拒绝旧管理提交。

## 授权、回执与扩展

所有工作区请求使用 POST，包含只读查询也要求当前会话和 CSRF。当前路由为：

```text
POST /api/v1/clients/{client}/accounts/{account}/targets/{target}/management/{resource}
```

聊天管理沿用以下资源；独立空间另使用[升级配置](web-console.md#484-l-升级配置)列出的实例资源：

| 资源 | 请求类型 | 能力 |
| --- | --- | --- |
| teaneko.agent:activity | AgentConsole.ActivityQuery | 有界脱敏活动查询 |
| agent.cognition:layers | AgentLayersConsole.Query | 三层读取、长期修正/遗忘、原回执查询 |
| agent.cognition:memory | AgentConsole.MemoryQuery | 证据事实分页、修正、克隆、换代清空、原回执查询 |
| agent.cognition:profiles | AgentConsole.ProfileQuery | 原事实画像投影 |
| agent.cognition:personality | AgentConsole.PersonalityQuery | 基础/补正查询、明确管理动作、原回执查询 |

例如首次活动请求为 `{"after":0,"limit":100}`；三层读取为 `{"action":"READ","namespace":"","generation":-1,"revision":-1,"topic":""}`。写入必须带原 operationId、明确目标及所需版本；请求类型由已注册资源固定，不允许选择 Java 类、方法、Bean 或存储类型。

WebManagementCalls 将真实会话映射到原 ManagementGateway 和唯一 IManagementAuthority，仅授权本次入口持有的同一上下文对象、本地资源白名单与插件代次。相同主体字符串、原生 OWNER/DEBUG 或猜到资源 ID 都不构成授权。进程最多保留 32 个在途管理调用，资源与控制随物理阶段结束释放；页面断开不能证明事务回滚。

管理来源标记为 MANAGEMENT，使用宿主派生的独立主体 UUID，不注册平台用户，也不能进入 Agent 模型活动。事务内通过 ManagementContext.checkActive 复核会话、平台/资源插件及白名单；不是只在请求线程检查一次。普通学习端口继续只接受原用户来源，领域 Store 仍经 Agent 专用 EasyData。

写入与原领域幂等回执同事务保存；失败或返回中断时页面保留原编号，可查原回执或原样重试，不能换编号猜测。冲突明确显示未提交新修改，不自动覆盖。回执沿用各领域的保留和旧代次回收规则，不承诺永久查询；未查到也不证明从未提交。回执只证明原操作结果，重新编辑前须读取当前状态。

插件继续实现原 IManagementResource 并以 Spring Bean 贡献明确 descriptor、requestType 和实际异步结果；新增资源需本地白名单明确开放，专用页面另按职责扩展。新写资源必须在真实副作用处调用上下文复核，并自行落实领域版本、持久幂等、审计和容量约束，网关不替插件补这些保证。详见[管理扩展指南](plugins/management.md)。

离线验证使用真实 MVC 安全链、原领域事务夹具与本机 Edge 的离线 API 契约夹具。真实数据库隔离、OneBot 交付、HTTPS/代理与公网仍按部署清单实机验证。

## 持久计划入口

4.7.0-l 新增“持久计划”分区，按当前聊天读取原计划，允许按版本取消未来执行并查询原事务回执；不伪造原生来源创建任务。完整状态、分页和在途动作边界见[任务与日志](web-console-runtime.md#agent-持久计划)。
