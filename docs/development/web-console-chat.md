# 网页聊天

当前版本为 4.8.2-l。登录后进入“网页聊天”，在私聊/群聊目录点击房间卡片即可进入聊天室，也可创建私聊或模拟群。聊天室的“聊天”页只保留消息和输入区；上方切换会话设置、成员与图片。返回按钮回到房间目录，同一房间草稿仍保留。网页使用独立 `web` client，消息交给现有命令、事件和 Agent 链。

房间标题旁显示 Agent 等待、上下文整理、模型/工具交互及结束状态，观察不会重复发送请求或重建输入框。状态来自当前进程的活动窗口；“已生成回复”表示模型完成，实际消息送达仍以聊天记录为准。切到其他页面或后台时停止轮询。

“聊天设置”中可选择已经应用的模型路由；空值继承文件默认。命令列表、模型添加与切换见[模型配置](web-console-models.md#切换聊天模型)。聊天名称来自原平台目录和应用级已观察资料，Agent 工作区刷新时读取最新名称；昵称不参与权限判断。

## 使用

首次访问会通过原 TeaUser 服务登记“网页用户”。新增档案时只填写昵称，平台号和 TeaNeko UUID 由服务器生成并持久保存。私聊选择一位档案，每个档案只有一个私聊；模拟群可以包含多位档案，发送时选择当前群已有成员。

私聊和模拟群的初始权限均为 MEMBER。聊天室顶部标签栏右侧的“权限”下拉对应当前发言档案，可在确认后切换 MEMBER / ADMIN / OWNER；群聊显示普通成员、群管理员和群主，私聊显示普通成员、管理员和所有者。切换沿用成员管理的预期版本和操作编号，保留输入草稿，不接受 DEBUG。私聊始终保留原有唯一成员，不能通过权限切换新增、替换或移除身份；群成员名片和其他成员角色仍在“成员”页管理。消息请求不能指定 UUID、scope 或角色，网页管理权限也不会自动成为聊天角色。角色只属于网页平台，不冒充 OneBot 联系人。

消息支持纯文本、提及当前 TeaNeko、引用和一张图片。输入区左侧“+”选择图片，也可将一张图片拖入输入区；上传完成后在正文上方预览，点击右上角“×”只取消本次附图，清理服务端未引用图片仍在“当前聊天图片”页操作。右侧箭头发送消息，也可用 Ctrl+Enter；普通回车换行，中文输入法组合输入期间不快捷发送。后台每两秒增量读取消息，不会禁用输入框或清空新草稿。

群聊可打开“提及 TeaNeko”；机器人身份固定为 `web-bot`，会正确识别正在提及自己。原客户端命令可以直接输入，继续执行原权限、作用域和插件限制。

网页私聊在创建、进入或提交消息时，为尚未登记的聊天原子登记并启用 Agent；已有记录（包括明确关闭）保持原值，群聊仍需手动启用。本地总开关、模型就绪、预算和插件状态继续生效。v4.7.6-l 的“聊天设置”“活动与记忆”是与聊天、会话设置并列的房间子页，保持在网页聊天栏内，无需重新选择平台或目标；“会话设置”的按钮也可进入同一子页。各房间分别保留配置草稿与待确认操作，返回或切换房间不混用；离开活动子页停止后台活动轮询。私聊无需提及，群聊沿用提及、引用、称呼及主动模式规则。

简洁模式以作者和正文摘要展示引用，点击可定位并突出原消息；原消息已离开当前窗口时明确提示。高级模式额外显示消息 ID 和引用 ID。输入 `/` 显示当前发言档案有权使用的指令，主指令后空格继续补全子指令；方向键选择，Tab/Enter 填入，Escape 关闭，Ctrl+Enter 仍用于发送。补全不执行命令，执行时仍由原分发器复核。独立“指令一览”展示所有已启用命令的说明、示例、参数、权限及客户端条件，管理员查看目录不会改变网页成员权限。

记忆 namespace 继续沿用原默认共享规则，同一网页档案在不同群使用同一 TeaNeko UUID；人格默认按实际聊天作用域独立。界面中的模拟群不会自动成为隔离记忆的沙箱，需要隔离时通过原 namespace 管理显式新建并绑定。网页聊天记录与 Agent 历史、三层记忆分别管理。

## 删除及失败提示

v4.8.2-l 起，目录卡片的垃圾桶按钮在一次不可恢复确认后删除该网页房间、消息和附件。删除保留用户档案、聊天配置以及 Agent 共享记忆；不能通过旧消息来源恢复已删除房间。重新建立同一档案的私聊时，保留的聊天配置仍可能继续生效。

当前发言档案的消息靠右，其他成员与机器人靠左。简洁模式不显示详细操作回执；正常提交不弹出待确认卡片，实际连接失败后才提供原请求查询及重试入口。

Agent 轮次失败默认通过原发送器提示具体原因，HTTP、网络、超时、表达格式错误和未知代码位置与后台诊断保持一致，不显示密钥或供应商原始响应。聊天设置可关闭“失败原因回复”，或在该聊天执行 `/cfg set agent failureReplyEnabled false`；重新开启设为 `true`。关闭、取消、撤权时不会补发迟到错误提示；发送器自身不可用时无法通过该发送器告知用户。

## 持久化、回执与重连

原平台档案、聊天、成员、消息、图片及受理账本经 GeneralEasyData 的 `web.chat.v1` 域和原 DTO 事务保存。目录、每个聊天窗口和每张图片分别存放，不依赖进程内消息计数或业务 Repository。Agent 自身数据继续使用 TeaNekoAgentEasyData。

| 回执 | 实际含义 |
| --- | --- |
| PERSISTED | 入站消息已提交，尚未证明事件通知、模型或回复完成 |
| DISPATCHED | 原入站事件与已登记的命令/Agent 处理阶段已结束；是否实际回复以聊天消息为准 |
| REJECTED | 原消息事件被取消；不推定已启动业务回滚 |
| INDETERMINATE | 事件通知、业务处理失败或原工作拥有者无法确认；查看活动与模型配置，不自动重放 |

每个消息操作使用原 UUID、聊天、档案、正文、图片、引用和服务端观察时刻，参数摘要与目标一起绑定。同编号重复提交只返回原事实，不重复触发事件；修改目标或参数会拒绝。新请求的观察时刻需在五分钟内。入站回执保留一天，每个聊天最多 512 项，全实例最多 4096 项；满时拒绝新受理。档案、聊天和成员管理回执单独保留一天、最多 256 项，旧创建编号不能覆盖仍存在的档案或聊天。

HTTP 错误或断开不能证明消息没有保存。页面在内存保留原请求，可查询原编号或原样重试；不会自动提交新编号。管理与上传请求同样保留原编号供明确重试。退出或刷新释放页面草稿，不将令牌、正文或文件写进 localStorage / sessionStorage。

聊天可见时每两秒按持久游标读取，隐藏时停止轮询；每页最多五十条，也可点击继续读取。刷新页面后重新选择原聊天即可补读，不重新发送原消息。窗口前移时明确提示重新定位，不把未显示的消息解释为未发生。

机器人发送仍由原发送器和 Agent 逐段交付链等待回执。返回的消息号证明服务端已提交该条消息，不代表浏览器已收到或用户已读；网页离线不删除聊天。原生发送与转发保持段序，转发节点以作者标签及原片段展示。无明确原生来源的独立群/私聊发送、踢人和 OneBot 专有动作不会借网页登录补出能力；当前也不承诺网页的持久离线定时发送。

原生网页来源支持 Core `ICommandSourceGuard`，命令分发与实际排队启动均复核；网页消息事件在实际出队、通知监听器之前也会检查原来源，避免提交后退出仍启动监听器。会话撤销、服务关闭或五分钟来源期限到达后不能新增发送；成员变更期间及之后旧来源也失效，发送事务还会核对当前成员版本。已受理模型或其他业务可能仍继续执行，不声称回滚外部 IO；宿主仍可保存已经发生的事实。首期只支持单应用实例，不支持多个副本共享内存会话和来源代次。

## 图片

上传和下载都使用原 HTTPS 会话；写入、删除另外要求 CSRF。客户端只提交文件字节或当前聊天已有图片号，不接受服务器路径、任意 URL 或原平台 JSON。原图和标准 PNG 均最多一 MiB，边长最多 4096、总像素最多 4,194,304，同时最多两次解码。支持 PNG、JPEG 和 GIF 首帧，统一重编码为静态 PNG，移除原名称和元数据，不保留动画。

图片以受限媒体号归属当前聊天，禁止跨聊天读取、引用或删除；下载为 `image/png` 且 `Cache-Control: no-store`。还在当前持久消息窗口中使用的图片不能删除，未引用图片可在“当前聊天图片”清理。容量满后拒绝新上传，不静默删除已引用内容。

送给模型的图片由后端内联，不把浏览器会话或认证下载地址交给模型。`web_get_message` 通过有效轮次来源读取当前聊天的引用消息，并把图片作为真实视觉结果回填；不能读取其他聊天。共享表情包和网页客户端表情使用原表达注册表，图片仍受网页限制，原生表情映射为 Unicode 单独发送。

## 本地配置与扩展

容量位于 `config/web/chat.yml`：

```yaml
max-rooms: 32
max-profiles: 16
max-messages: 500
max-media: 64
```

允许范围依次为 1–128、1–32、50–2000、1–128。`web.chat` 文件区可通过原文件配置页面保存并独立热应用；旧安全文件的 `file-sections` 需手动加入该区。下调容量不删除既有档案、聊天或图片，消息窗口在后续追加时裁剪。

平台通过 `@TeaNekoClient("web")` 和工具箱注册，管理适配器通过 `@TeaNekoClientManagement("web")` 发现。插件可以监听 `WebMessageReceiveEvent` 或通用 `TeaNekoMessageReceiveEvent<?>`；运行时沿实际事件继承关系合并监听器，不要求子事件先被类扫描发现。同一处理器只调用一次。同步监听器可调用 `event.trackProcessing(stage)` 登记实际异步业务，网页在通知结束后统一等待，禁止结束后追加；其他未登记的后台任务不计入该回执。房间准备扩展见[管理插件指南](plugins/management.md#网页房间与模型配置扩展)。Agent 工具沿用 `@TeaNekoAgentToolClass(client = "web")`，表达沿用 `@TeaNekoExpressionClient("web")`。历史对象保持只读。

HTTP 入口为 `/api/v1/chat` 下的 GET/POST `rooms`、POST `profiles`、POST `rooms/{room}/open`、POST `rooms/{room}/commands`（`profile` 为房间已有成员）、POST `rooms/{room}/members`、GET/POST `rooms/{room}/messages`、GET `rooms/{room}/operations/{UUID}`，以及该聊天的 GET/POST `media`、GET/DELETE `media/{id}`。上传使用 `application/octet-stream` 和查询参数 `operation`。所有目标必须已由服务端登记，写请求继续要求 CSRF。全局指令目录位于 GET `/api/v1/commands`。

离线验证使用原事务夹具、真实 Spring/scanner 平台装配、MVC 安全链及本机浏览器契约夹具，不调用真实模型或数据库。部署前仍须验证 MySQL/JPA、多浏览器并发、正式证书/代理、登录撤权、模型视觉能力及实际分段表达；清单见[控制台部署](web-console.md#验证与实机待办)。
