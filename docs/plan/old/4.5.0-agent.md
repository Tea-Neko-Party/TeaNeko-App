## 必须保持的边界

- 复用 Core 执行/任务/事务、LLM 协议及 Agent 端口，按低层到高层解耦；组件不保存客户端、Bean、仓库或密钥。
- scope 未注册或禁用时，不执行对话、模型工具、采集、摘要及自主任务；帮助、状态和配置启用入口可达。
- 真实原生来源决定 UUID、client、scope 和权限；模型、Skill、历史文本及系统任务不能自行声明身份或 DEBUG。
- 长期记忆按 namespace 共享，画像按 namespace+UUID，保留主体及来源；原始历史默认只查当前有效 scope/绑定/代次。
- OWNER 可绑定已有他人空间；reset 创建并切换新空空间，保留原数据。clear/导出/编辑/克隆仅 DEBUG；correctionKey 用独立 DEBUG 指令，不经 /cfg 修改。
- 基础人格、补正与画像独立；切人格先备份，再仅切当前 scope 的新空补正引用并重建短期会话，保留其他共享引用。
- 每轮固定可信引用，副作用、提交和发送前复核当前准入及 generation/epoch；切换或 clear 后旧轮/后台任务不得回灌。
- 默认预算为 3 次模型、2 轮工具、6 次工具执行，可配置或显式降低；前台子步骤共用总预算，独立后台任务有独立受限预算。
- 所有命令方法返回 CompletionStage<?>，通常为 CompletionStage<Void>，包含真实业务/反馈等待；处理结束不等于业务成功，写副作用不盲目重试，取消不声称回滚。
- 模型默认路由、参数、密钥、连接与 metadata 统一在本地 model.yml 配置，Core YAML 统一解析环境占位符；凭据不经聊天写入，不进入 Prompt、业务组件、普通导出或日志，不回退到旧 application 供应商配置。
- 每批完成一个功能闭环，只补必要测试；复用未变化的阅读/验证结论。报告只写新增交付、验证摘要、限制和下一步，详细日志落盘。
- 实现任务默认不执行真实提交、标签、推送、版本升级或旧包删除；用户明确要求执行时按对应流程办理。修改版本任务本身不等于立即发布。
