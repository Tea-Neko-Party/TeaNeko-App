## 实施顺序

各阶段按可使用的功能闭环交付，包含后端、页面、必要测试及文档。下列百分比是累计工作量预估，实际进度按完成情况调整，不按固定百分比切碎开发。

| 阶段 | 完整交付内容 | 完成后的预计进度 |
| --- | --- | --- |
| P1 | 简洁登录、响应式导航、统一主题、简洁/高级模式及现有页面交互整理 | 20% |
| P2 | 机器令牌新规则、网页查看/修改/应用、启动与记忆失败诊断、连接入口说明 | 40% |
| P3 | 自动发现配置管理器、中文字段表单、聊天区域登记/修改/注销、Agent 与其他配置分区 | 65% |
| P4 | 注解式任务展示和分类、当前任务分类接入、服务端筛选与网页操作 | 80% |
| P5 | CPU/内存采样、真实运行版本、概览页面接入及刷新生命周期 | 90% |
| P6 | 关键用户流程回归、隔离编译、构建产物核对、操作说明与补丁日志 | 100% |

## 实施约束

- 先完善 Core 和领域接口，再实现 Web 应用层与页面；沿用 Vue、TypeScript、Element Plus 和现有事件、扫描、配置及管理网关。
- 新类型的 `@since`、`@version` 使用 `4.7.1-l`；实质修改的已有类型保留 `@since`、`@date`，更新 `@version` 及实际修改记录。
- 继续复用专用 EasyData 入口、事务、字段校验、版本仲裁和操作回执，不在网页层直接操作数据库 Repository。
- 不自动部署、提交 Git、打标签、切换工作树或停止当前机器人。验证优先使用隔离构建目录。
- 参考资料和对照记录仅放在 `temp/`；正式代码、注释、文档、资源和日志只使用 TeaNeko 自身命名，不复制参考界面的源码、品牌素材和文案。
- 每个阶段只补必要测试；实现并验收全部约定范围后归档本计划及配套规格，实机部署检查单独保留。
