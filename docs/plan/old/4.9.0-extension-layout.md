## 审查时的剩余事项与实施次序（已完成）

2026/11/07：用户要求先说明剩余任务，重新审查扩展方式并重构不合规实现。审查当时源码仍处于编译修复阶段，旧版回归和先前前端检查不代表当时完整交付。下列五项现已完成，最终结果见上方本轮验证。

1. 删除 `AgentScopeConfigData` 临时增加的业务访问器；组件声明维护参数约束，各插件配置适配器通过 `AgentComponentAccess` 读取有效装配。保留原始未知 JSON 节点，迁移不能因 Jackson 忽略属性丢值。
2. 清理宿主主动触发与会话窗口中的业务知识，完成上下文、回复交付和客户端操作的类型化适配。接口只围绕已存在的消费者设立，不能把中央业务分支换成中央字段表。
3. 检查人格文件配置等遗漏的业务类型、插件归属、原生模型与工具、LLM 独立性以及运行路径的发现扫描。
4. 完成注解注册、默认开放授权、插件启停、隐藏配置保留和迁移回归，先恢复生产编译，再验证受影响测试与前端。
5. 同步开发说明和发布说明，清理有证据的空目录，运行 JavaDoc、分层检查与差异检查，核对实际 JAR；实机验收单列。

保留方向：注解静态声明、独立宿主身份、分类插件、前端模块目录与默认开放的可选白名单。
放弃方向：宿主为每个插件添加 getter/setter、固定业务标识判断、靠旧接口桥接掩盖逆向依赖，以及只迁移包名而未迁移职责的实现。
