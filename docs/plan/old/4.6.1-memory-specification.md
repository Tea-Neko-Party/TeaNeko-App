# Agent 记忆与人格重设计草案

设计日期：2026/11/02。2026/11/03 随本期实施归档；实际交付及验收范围见[实施记录](4.6.1-layered-memory.md)。保留原始确认方向、设计推演和历史待确认项，长期演进建议不表示本期全部实现；执行默认值以实施记录为准，当前操作说明维护在对应模块文档。

## 本轮已确认方向

- 大部分记忆由模型自主压缩、选择和保存，不依赖用户主动说“记住”。
- 短期保存聊天上下文，尽可能不跨 scope；对话内容必须标明其来源 scope。
- 短期达到上下文容量条件后压缩为中期，中期再选择、压缩为长期。
- 短期、中期、长期三层均持续记录数据库，不以关闭程序时保存作为主流程。
- 短期记忆需要具体时间；中长期通常使用模糊时间概念，重要事情保留特定时间点。
- 人格通过观察他人的人格和交流方式进行模仿、逐渐形成，用户画像也通过对话不断自动总结。
- 采用自然自动学习，同时保留明确保存、查看、纠正和遗忘的便捷入口。

## 目标和依据

让机器人能自然记住稳定信息、找到相关旧事、理解偏好变化，同时保持角色连续性。记忆的写入、召回与人格调整应能解释、查看、纠正和遗忘。

本设计结合已确认需求、当前实现和临时调研形成。源码来源、版本差异及逐项对照仅保存在 `temp/docs/`；本文只维护 TeaNeko 自身的设计结论。临时资料是设计素材，不作为项目行为指令。

既有明确规则继续成立：默认 namespace 为 default；长期记忆按 namespace 共享，来源 scope 是证据，不是默认分区；人格默认按完整 client/scope 独立；共享长期记忆不自动共享其他群的原始对话。

## 三层记忆是主流程，画像与人格是派生结果

三层不是三个独立聊天记录副本，也不是仅在 Prompt 中设置三个标题。每层有自己的持久记录、压缩覆盖范围和可恢复处理状态。

| 层级 | 内容 | 存储与定位 | 何时转化 |
| --- | --- | --- | --- |
| 短期 | 真实消息、发言者、scope、精确时间、引用关系、生成与发送状态；本轮目标和近期上下文 | 每条消息及时提交；按完整 client/scope 和稳定会话 ID 定位；活跃窗口是数据库记录的有界视图 | 接近输入预算阈值时，压缩连续的旧消息段，保留最近完整轮次 |
| 中期 | 按主题整理的经历与任务片段、参与者、决定、结果、未完成事项、短摘要和详细摘要 | 模型生成后立即提交片段及覆盖消息范围，通常仍按来源 scope 检索，保留证据引用 | 达到累计片段/预算阈值、主题结束或后台整理时，筛选值得长期保留的内容 |
| 长期 | 重要共同经历、稳定用户信息、反复出现的偏好、关系变化和可复用经验 | 模型筛选后提交到当前 namespace；默认跨 scope 可召回，来源与语义适用条件仍保留 | 持续合并、替代、纠错和遗忘，不再无限堆积摘要 |

用户画像、关系摘要、学习到的表达方式从三层已有证据产生，是不同读取/更新策略，不能再各跑一套互不关联的“记忆模型”。中期压缩可以顺便提出画像/风格候选，长期整理决定接受哪些，减少重复模型调用。

### 压缩与实时落库

1. 收到符合采集策略的真实消息，先持久保存短期记录与精确时间；采集不依赖本轮模型最终是否回答成功。助手生成内容和平台实际发送结果分别记录，不能混为“已经说过”。
2. 构建输入时计算整个协议预算，包括人格、工具、记忆和输出预留；短期可用预算不是供应商上下文的全部容量。建议在可用窗口的约 70%–80% 提前安排压缩，比例只是初始建议，需实测。
3. 固定一段连续消息范围和指纹，模型生成中期摘要；成功提交摘要、来源覆盖和处理水位后，才能从活跃窗口移除对应短期片段。原始记录继续按保留策略存在。
4. 同一 scope 的压缩任务有序处理覆盖区间，采用后到的消息作为新尾部；跨 scope 可以并行。数据库等待和模型请求不占会话锁。
5. 后台整理中期片段，输出“长期条目 + 画像变化 + 模仿风格候选 + 未解决冲突”。模型可以决定不长期保存闲聊，但中期是否到期由独立政策决定。
6. 长期提交使用原片段 ID、水位和稳定任务 ID 去重；只处理增量，避免每轮读取全部历史或反复对整个旧摘要进行有损压缩。

“实时”表示消息及时提交、摘要和长期结论在生成后及时提交；不表示每条消息同步调用三个模型。明确“记住”可走同一校验管线的优先提交，不必等待两次批处理。

压缩失败不推进覆盖水位，不宣称对应旧消息已经被记住。前台预算不足时优先读取已提交中期片段；确需紧急压缩时有界等待一次，仍失败则返回明确降级状态，原数据库记录保留以便恢复。不能用无限等待维持所谓完整记忆。

### 时间：存储可追溯，回忆有精度

| 数据 | 推荐时间表达 |
| --- | --- |
| 短期消息 | 原始 Instant、平台来源和必要时区；缺少原时间标注估算 |
| 中期经历 | 有绝对锚点的范围与精度，例如“2026 年 11 月初的一次讨论”，并链接真实消息时间 |
| 长期普通经历 | “第一次讨论项目时”“大约上个月”“某段时间”，内部关联绝对锚点，随查询时间重新表达 |
| 重要日期或明确约定 | 保留原始精确日期/时间与时区，例如截止时间、预约、纪念日；只有日期时不能补造时分秒 |

具体结构建议为 eventStart/eventEnd、precision、anchor、originalExpression、recordedAt、timeImportance。模糊时间不是让模型随机说“大概”，而是摘要降低展示精度、底层保留证据锚点；也不能把保存时间冒充事件发生时间。

重要度候选可由模型提出，但用户明确日期、任务截止等由业务规则保留。角色推测的重要日期不能替代原证据。长期条目可以记得某件事，却不必每次复述精确到秒的时间。

### 默认如何使用三层

先使用当前 scope 的短期上下文，再补相关中期片段，必要时从共享 namespace 取长期记忆。普通聊天不加载其他 scope 的短期原文。共享长期结果可说明“此前在某个群聊中提到”，是否展示具体群标识按实际访问策略决定。

当前用户新说的“我已经不喝咖啡了”首先进入短期，并立即影响本次理解；长期版本尚未更新时也不能用旧画像反驳用户。后台再把变化合并进长期和画像。中期、长期摘要不能把“某人猜测”压缩为无来源的确定事实。

## 三层中保存的语义内容

| 数据 | 回答的问题 | 生命周期和定位 |
| --- | --- | --- |
| 原始对话证据 | 当时具体说了什么？ | 按 client/scope 的会话权限保存，保留消息 ID、真实作者和时间 |
| 当前工作上下文 | 这轮在讨论什么、做到哪了？ | 当前会话窗口，保存目标、决策、待办与近期消息；有界 |
| 事件记忆 | 发生过什么共同经历？ | namespace 内的事件摘要，链接原证据，支持事件时间和参与者 |
| 稳定事实/用户偏好 | 谁的什么信息目前可信？ | namespace + 主体 + 语义属性，支持确认、替代、冲突和失效 |
| 人格与互动状态 | 我是谁、在这里如何表达、如何与这个人相处？ | 基础角色、scope 风格、关系和短时状态分别管理 |

用户画像是事实的读取投影，不再维护一份无证据的画像正文。会话摘要与事件记忆可以共用摘要结果，但前者服务窗口续接，后者必须经过独立的长期保留判断。

## 定位：共享范围、主体、适用条件分开

建议在业务对象中明确四个维度：

1. namespace 决定长期记忆空间，默认跨 scope 可检索。
2. subject 决定信息属于谁：优先使用真实 TeaNeko UUID；事件也可关联群体、项目等已解析实体。
3. source 记录信息来自哪个 client/scope、作者、消息和时间，供追溯与访问检查。
4. applicability 表示语义适用条件，例如“仅技术问题偏好详细回答”“在 A 群使用这个群昵称”。

applicability 用于相关性判断，不是恢复按来源 scope 隐式隔离。用户在 A 群说“我住杭州”，在共享 namespace 的 B 群仍可召回；“我在 A 群担任管理员”不能被解释为 B 群身份。

别名仅辅助检索，不直接绑定身份；同名用户不能合并，引用消息的作者也不能当成本轮作者。自动事实默认接受本人自述，第三方陈述保持“某人声称”的证据性质，不自动改写他人已确认资料。

未来多 Agent 时，用户事实仍可按 namespace 共享；角色成长与关系增加持久的 agentIdentity/persona 标识，不使用随机运行实例 EntityId 作为长期身份。

## 事实从证据到结论

建议事实分成“断言及其版本”和“证据引用”，最小信息包括：

- 断言：id、namespace/generation、subject、predicate、value、status、revision。
- 适用性：context、validFrom/validTo、eventTime、记录时间、expiresAt；未知事件时间不伪造。
- 依据：来源消息/事件 ID、作者、来源种类、必要的证据片段、extractionVersion。
- 演变：supersedes、conflictsWith、confirmation、locked、遗忘标记。

predicate 为可扩展的语义属性，首批使用少量常见属性和自由事实兜底，不试图提前穷举世界知识。证据片段受自身访问及保留策略控制，普通召回只返回允许的摘要与引用。

处理规则：

| 情况 | 推荐处理 |
| --- | --- |
| 用户再次表达相同事实 | 关联新证据，不重复增加一条有效结论；重复转述不当作独立确认 |
| 同主体、单值属性明确改变 | 新版本替代旧版本，保留时间关系；“后来变化”不必视为历史错误 |
| 多值偏好可以共存 | 合并到并列偏好，不把“也喜欢咖啡”当作否定绿茶 |
| 否定、撤回或更正 | 记录更正证据，明确失效目标，不简单按最近文本覆盖 |
| 缺少主体、时间或指代不清 | 留在会话上下文或候选中，需要时澄清 |
| 两个来源矛盾且无法判定 | 保留冲突，降低直接断言强度，检索返回分歧 |
| 用户忘记某条信息 | 授权检查后立即从有效召回排除，后续清理派生投影与索引 |

来源可靠度、用户确认与模型 confidence 分开。模型自己报告 0.95 不能等同事实可靠；“置信度提高”不授予额外权限。锁定事实不能被后台学习自动覆盖。

## 写入：明确保存和自然学习共用一条管线

用户已确认以自然学习为主：由短期到中期再到长期的自动整理积累信息；明确要求“记住”只是优先通道。两者都经过证据、领域和权限校验。

```mermaid
flowchart LR
    A[真实消息证据] --> B[稳定信息及显式意图检测]
    B --> C[有界候选抽取]
    C --> D[主体与证据校验]
    D --> E[查找重复、替代及冲突]
    E --> F[事务提交断言和回执]
    F --> G[更新可重建索引与投影]
```

明确请求：

- 可支持“以后叫我小茶”“记住我不喝咖啡”“刚才那条记错了”等自然表述。
- LLM 只提出内容和候选操作，不创建 authorized、actor、namespace 或目标用户身份。
- “已记住”必须来自真实提交回执。可以在回答中等待这项必要保存，不再依赖主模型恰好调用 memory_add。
- 无法稳定识别目标的修改/遗忘需澄清，不为任意描述执行整库删除。

自然学习：

- 先以稳定自述事实、明确称呼和表达偏好为范围，不保存所有闲聊。
- 已持久保存的合格短期消息生成可恢复压缩任务；按连续区间、预算或主题边界抽取，中期整理再筛选长期，不每轮再加一次分类模型和一次抽取模型。
- 群聊旁观采集不自动等同长期学习资格；建议先只学习与机器人直接互动的真实发言，是否学习旁观内容单独确认。
- 用户原话是用户事实证据；助手回答、摘要、引用转发和工具文本不能变成本人自述。已验证工具事实另走独立来源种类。
- 不把玩笑、假设、一次性任务指令和短时情绪直接提升为稳定事实。

原始证据与派生任务的最小可靠边界需要同事务提交，或提供可恢复扫描水位；不能宣称跨独立服务提交自动具备原子性。

## 召回：少量相关自动注入，复杂问题按需展开

第一层：当前上下文、当前用户少量稳定偏好、当前参与者及引用对象。身份来自宿主，不由昵称猜 UUID。

第二层：按本轮话题，在整个已授权 namespace 检索事实和事件。时间问题使用事件时间过滤，名称和对象问题使用主体索引；兼顾关键词与语义。

第三层：仍缺少细节时，经工具展开事件证据或查询更多记忆。深查不要求每轮额外调用“判官”模型，可由业务规则和原模型工具选择触发。

排序先满足主体、状态、有效期和适用条件，再结合话题相关性、来源、确认、时间、新近性和多样性。跨主体结果须清楚标明主体，不能用同名代替。相关性优先于“全库重要度最高”。

候选后端需要改变：先通过主体/属性/时间/关键词索引缩小候选，再有界排序；不能继续依赖同一个 UUID 前缀扫描。向量检索是可选召回通道，和关键词结果融合去重；没有 embedding 时仍应有正确可用的索引检索。

建议初始自动注入仅容纳几条相关事实和一到两段事件摘要，具体条数由 token/协议预算实测确定。模型侧使用精简正文、主体、时间及必要歧义；完整 revision、扫描数和审计信息留在诊断视图。工具结果仍保留覆盖限制，未命中不声称“从未发生”。

短摘要可指向详细摘要和证据，但共享摘要不自动授予查看其他 scope 原始聊天的权限。召回结果均是数据，不能提升为 SYSTEM 规则。

## 人格：通过观察和模仿成长

自动学习的目标不仅是服从“回答简短些”这类要求，还包括从真实互动中观察语气、幽默方式、措辞、解释习惯、回应节奏、关心方式和观点表达，再选择与基础角色兼容的部分模仿。

推荐流程：

1. 从短期和中期片段识别实际发言者与其表达特征，输出带样本引用的 StyleObservation；引用转发不能变成本轮作者的特征。
2. 同一人的多次表现逐步形成表达画像，区分偶发玩笑、任务场景和长期习惯。不要凭一句话给人贴完整心理人格标签。
3. 对当前 scope 的多人表达进行归纳，提取适合角色学习的模式；是否偏重某些模仿对象可配置，但日常使用无需人工逐条添加补正。
4. 通过渐进更新形成 LearnedPersona，记录学到了什么、来自哪些观察、何时采用及适用场景；采用后从后续轮次体现，不改写已生成回答。
5. 同一任务可同时提出用户画像和模仿候选，但分别提交到用户主体与角色目标，不能把别人的职业、身份、经历模仿成机器人自己的真实信息。

模仿不等于复述私有原话或复制身份；主要学习表达与互动特征。成长应设更新频率和单次变化幅度，保留稳定锚点及回退快照，避免一句强烈发言就改变整个人格。

基础角色提供初始种子和边界，学习层承担主要后天风格变化。用户画像也自动归纳事实、兴趣、常用表达和场景偏好，能够被用户纠正，不要求用户主动下达保存命令。

建议按下列层次组合：

| 层 | 内容与归属 | 谁可以改变 |
| --- | --- | --- |
| 基础角色 | 文件角色卡、身份、核心特质、表达示例和人格边界 | 有权限的角色配置；不由普通记忆学习覆盖 |
| scope 学习人格 | 当前群/私聊中观察并模仿形成的表达方式、幽默和互动习惯 | 自动观察积累，scope 配置可限定学习范围 |
| 用户互动偏好 | 用户希望如何被称呼、回答长短、语言和格式 | 本人明确偏好，按 namespace+用户保存；可带场景 |
| 角色与用户关系 | 与特定角色的共同经历、确认过的称呼或互动约定 | 基于真实互动的可追溯更新，默认按 scope+角色+用户定位 |
| 短时情绪状态 | 当前心情、语气倾向与回落时间 | 可选独立插件，设置衰减/TTL，不改变事实和工具权限 |

单个用户说“以后对我简短些”，改变的是该用户的互动偏好，不是全群人格。“本次简短些”只影响当前轮次。群体风格主要由反复观察的交流习惯积累，管理员配置是可选引导，不是学习的前提。

基础角色和学习记录分离，但不建议直接保存一份不断增长、任意改写的 SOUL.md。可由结构化记录生成一段可查看的成长摘要；摘要是投影，不能成为第二份权威事实。

不默认添加数值好感度、敌意或“爆发模式”。如未来需要，作为可替换状态插件明确设计，不能因情绪越过权限、惩罚用户或修改记忆事实。

人格解析输出稳定角色指纹、已采用的 scope 学习人格、适用风格及有限互动偏好；候选携带目标、观察依据和适用范围，不再把所有表达补正不加区分地加入同一个集合。更换基础角色后，只复核角色相关修正的兼容性；用户姓名和饮食偏好不因换角色失效。

## 历史、清理和关闭程序

清上下文、删除长期记忆、重置角色成长必须是独立操作，分别说明范围。保留现有 clear 的已公开语义，未来如调整命令应显式设计兼容，不静默让它改为另一种操作。

建议历史定位以稳定的会话来源和会话 ID 为主，记录当时 namespace/persona 标签；人格更新不物理丢失原始证据。默认窗口是否携带旧角色内容由选择策略决定，原文的删除仍受其独立保留期控制。

持久化是运行中的连续行为，不能依赖 JVM 退出时才保存：

1. 原消息证据及学习任务先可靠保存，明确保存返回真实事务回执。
2. 后台任务用稳定 jobId、处理水位及运行租约恢复；崩溃后重跑仍经过幂等和当前策略。
3. 正常关闭先停止接收新任务，在有界期限内等待已启动任务；未完成任务保留持久状态，重启继续。
4. 强制终止不保证内存任务完成；恢复依赖已提交记录。需要提取的证据应保留至任务完成，超出保留政策时明确失败或取消。

任务固定原 namespace/generation、原人格目标、原作者与政策版本。切换空间、clear、遗忘或权限变化后重新核对，不把旧结果改投新目标。

遗忘先事务写入失效/墓碑，再异步清理索引、缓存及向量；旧索引命中必须回查当前状态。后续学习不能从同一旧证据把已遗忘信息重新抽回来。遗忘是否同时删除原聊天历史、是否允许用户未来主动重新告知，须作为明确的产品语义确认。

## 从底层到高层的接口

下列名称为职责草案，不是本次要全部新建的类清单；可复用既有端口时原位扩展。

| 层 | 端口或契约 | 责任 |
| --- | --- | --- |
| 领域标识与证据 | MemoryContext、EvidenceRef、MemorySubject | 固定空间、主体、来源、时间和可用策略 |
| 持久化 | 事实/证据 Store、LearningJobStore | 事务、幂等、版本、墓碑、任务恢复；业务仅通过 TeaNekoAgentEasyData DTO |
| 分层记忆 | ShortTermStore、EpisodeStore、LongTermStore、MemoryConsolidationService | 三层持续落库、覆盖区间、水位、短到中压缩与中到长整理 |
| 候选检索 | IMemoryCandidateIndex、可选 IEmbeddingProvider | 主体/属性/时间/全文/语义候选；结果可重建，不持有真相 |
| 写入协调 | IMemoryExtractor、MemoryReconciliationService | 抽取结构化候选、证据验证、重复和冲突处理；模型无直接写库权 |
| 读取投影 | MemoryRecallService、ProfileProjector、EpisodeService | 有界召回、画像和事件，统一解释来源与覆盖 |
| 观察与人格 | IStyleObservationExtractor、PersonaLearningService、PersonalityResolver | 自动观察模仿、渐进采用、角色/群风格/用户偏好/关系的组合，不执行数据库底层操作 |
| 上下文组装 | MemoryContextContributor、PersonaContextContributor | 独立预算的 Prompt 片段与使用前校验 |
| 宿主接入 | 注解工具、Agent System、事件、管理资源 | 接收真实消息、提交作业、查询和反馈；不复制底层逻辑 |

继续使用现有 LLM 服务、CompletionStage、执行控制、数据库任务和借用执行器，不自建模型循环、重试系统或线程池。

ECS 适合保存每轮不可变的 MemoryContext、RecallBundle、ResolvedPersona 和参与者集合；System 负责有序协调，服务负责业务逻辑。Bean、仓库、线程池和完整原始聊天不塞入组件，跨轮持久状态也不只保存在 Entity 内存。

插件扩展点优先提供提取器、召回通道、排序策略、人格表达器与事件观察。候选事件可过滤或补充可校验候选，宿主之后统一校验；不能让监听器替换可信主体、扩大 namespace 或跳过原事务。提交后的事件只通知，不决定是否真正写入。工具继续用本版注解入口。

未来 Web 通过管理 SPI 查询有效记忆、证据、替代链、候选队列、学习任务和召回解释；修改仍进入相同领域服务，禁止直接改索引或数据库 JSON。具体涉及的用户/群权限与审计沿用宿主身份。

## 推荐实施顺序与验收

| 顺序 | 完整功能目标 | 主要验收场景 |
| --- | --- | --- |
| 一 | 短期消息实时落库、稳定会话恢复和时间定位 | 重启恢复近期上下文；默认不混入其他 scope；生成/发送状态和消息时间准确 |
| 二 | 持久中期摘要、自动压缩与可恢复任务 | 短期接近预算自动生成中期；提交后推进覆盖；崩溃恢复不丢消息、不重复压缩 |
| 三 | 中期到长期自动整理、持续用户画像 | 用户不说“记住”也能积累重要经历和稳定信息；模糊时间有锚点，关键日期不丢失；更新与矛盾可解释 |
| 四 | 相关性召回、索引与纠错/遗忘闭环 | 跨 scope 共享长期有效；大空间可定位目标；新近更正优先；已遗忘旧证据不复活 |
| 五 | 观察模仿与渐进人格成长 | 能从反复交流中学到表达方式；可查看依据；对 A 的偏好不误施给 B；换角色保留用户事实 |
| 六 | 可选 embedding、关系成长、情绪和 Web 展示 | 通过插件替换，关闭后基本记忆仍可用；是否实施按实际需求决定 |

每阶段交付完整功能闭环，仅测试关键业务与高风险边界，不按固定百分比切碎。首次改动前先盘点实际存量数据，决定保留或重建；早期“尚未上线、不迁移”的历史决定不能直接作为删除现在数据的授权。

## 核验后的具体落地约束

### 持久化对象及职责

下表为逻辑数据契约，不要求新增多个物理表。继续通过 TeaNekoAgentEasyData 入口管理，实际 schema 版本及迁移策略在实施前根据存量数据决定。

| 对象 | 关键数据 | 必须保证 |
| --- | --- | --- |
| ShortTermMessage | 稳定会话、消息序号、client/scope、作者 UUID、精确时间、内容、引用、生成/发送状态 | 每条记录及时提交；来源、正文和去重标识一致；清上下文后不恢复旧活跃窗口 |
| MediumTermSegment | 源序号区间及指纹、主题、参与者、时间精度、brief、details、决策和待办 | 不用单份无界滚动正文替代所有消息；有界摘要、分段保留、可以按证据展开 |
| LongTermEntry | 事实/偏好/经历类型、主体、内容、有效时间、原片段、替代与冲突关系 | 自动筛选、版本化合并、证据可追溯；长期重要性不由检索次数决定 |
| UserProfileProjection | 主体、有效事实引用、常见偏好、已确认变化、表达观察引用 | 无需用户主动保存；投影可以持久缓存，但不是独立于证据的第二份真相 |
| StyleObservation / LearnedExpression | 真实发言来源、适用场景、观察到的模式、支持样本、采用状态 | 记录“何时怎样表达”，不把身份与经历当作模仿对象；本轮只选少量适用项 |
| ConsolidationJob / Checkpoint | 原空间与代次、源范围、输入指纹、政策版本、租约、尝试次数、处理水位 | 待处理状态可恢复；稳定 jobId 防重；成功提交后才能推进水位 |
| IndexChange | 原记录及版本、索引动作、执行状态 | 与权威变更同事务保存，再异步更新搜索/向量索引 |

中期结果可以附带画像和表达观察候选，因此同一批对话通常只需一次结构化模型抽取。角色采用、事实更新和画像投影仍由各自领域服务处理，避免一个总服务兼管全部职责。

### 压缩的完成标准

模型返回内容只是候选，满足下列条件才能替代活跃窗口中的旧段：

1. 所有来源 ID 都属于本作业固定的真实消息范围，作者和时间关系可解释。
2. 输出满足结构、字符和 token/协议预算；确实减少输入占用，不能通过复述全部原文制造“摘要”。
3. 保留当前目标、重要决定、纠正和未完成事项；事实、猜测、建议与已执行结果不能混写。
4. 最近完整轮次继续保留，工具调用和结果不能在协议层被截成孤立条目。
5. 摘要、证据覆盖与水位在事务中提交；提交前再次核对空间代次、清理标记、遗忘状态和输入指纹。

正常续接的新消息不会令已固定旧区间全部作废；只有源区间被编辑、撤销、清理或目标身份发生不兼容变化时，才拒绝旧候选。这样避免活跃群持续有新消息，压缩就一直无法提交。

多个中期段整理成长期时，各源段可独立标记 processed，但不能一生成长期就删除全部中期。压缩覆盖、水位推进、活跃窗口释放和数据库到期清理是四种不同操作。

### 任务恢复和索引一致性

推荐作业状态为 PENDING → RUNNING → COMMITTED；RUNNING 使用租约，进程退出或租约过期后可重新领取。临时失败进入有限重试，永久失败、证据到期和明确跳过分别保留原因，不在查询时假装作业已完成。

同一源范围、同一算法版本的重复作业不能重复增加事实，也不能把同一段话算成多次独立观察。后台可调整并发与成本，但不能靠内存队列是否装得下决定已经接收的消息会不会永久丢失。

搜索和向量索引不是权威存储。数据库提交后索引更新失败可以补偿；删除或失效后的旧索引命中，回查权威记录及版本时排除。查询未命中与索引尚未追上分别诊断，不放宽 namespace 试图“找到点东西”。

### 人格观察与采用分离

观察对象是已授权采集的真实人类发言。机器人自己的回答、内部规划、检索回填和此前生成的摘要不是新的人类风格证据；摘要可以携带原始样本引用，但反复摘要不能增加支持次数。

表达候选至少包含“场景、表达模式、真实来源、适用对象”，先累计，再采用。每轮按当前场景和互动对象选少量已采用候选，不把整份成长档案常驻 Prompt。

学习频率和回复频率解耦：普通回复不必额外等待人格分析；观察可以随中期压缩提交，采用按周期或足够新证据渐进更新。新风格稳定性不足时先保留候选，不需要用户逐条审批，也不立即改写整个人格。

### 首期范围及成本

- 优先交付三层持久化、自然压缩、自动用户画像和真实观察学习；不以“模型没主动调用保存工具”为跳过理由。
- 普通一条消息不必额外调用模型。达到预算/主题条件才做中期压缩；积累足够中期片段才做长期整理；两种结果均可带画像/风格候选，避免重复分析同一批原文。
- 基础检索先支持主体、时间、关键词及必要排序；语义通道可插拔，图数据库与复杂数学重排不是第一期前置依赖。
- 长期保留考虑稳定性、独特经历、明确重要性和证据，而非只保留经常被询问的内容。低频但重要的约定不应自动消失。
- 默认不随机注入无关旧事，也不通过提示词催促高频工具调用来维持记忆。先解决连续性和相关性，主动回忆可后续作为独立插件设计。

## 待确认

- 自动三层压缩与观察式人格方向已确认，不再作为待选项；仍可补充一到两个真实对话例子用于验收。
- 群聊旁观内容是否参与学习，或先只学习直接互动。
- 关系是否也跨 scope 共享；默认建议人格与关系按 scope 独立，用户事实和偏好继续共享。
- 遗忘是否删除原始历史；自动学习与原文保留期需要分别设置。
- 现有记忆是否需要保留；在确认前不执行清库或格式迁移。
