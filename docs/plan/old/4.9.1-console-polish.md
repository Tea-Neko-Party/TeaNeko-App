# v4.9.1-l 插件控制台与模型同步

当前状态：2026/11/10 已完成并归档，3/3 个闭环（100%）完成。保留工作区既有 v4.9.0-l 诊断修正及用户的 gradle.properties 改动。未提交、打标签或部署。

## 范围与实现

1. 插件入口与管理：主侧栏右侧增加独立二级导航；插件管理置于管理组首位；名称优先展示、名称和 ID 均可筛选；右上角开关、底部对齐的主题色操作、有实际贡献才显示配置跳转；已安装功能改为分领域且可快速导航的弹窗。
2. 活动时间线：系统原生活动资源不检查业务插件启用状态，仍保留真实认证、资源权限及业务插件停用检查。
3. 模型同步与交付：模型页使用既有保存/应用事务自动应用成功保存的版本；未确认结果保留原编号，应用失败不报告成功。LLM 目录重新读取不覆盖聊天草稿；默认模型排首位，继承默认的聊天按新请求动态解析，显式路由及私有模型不改写。完成定向 Java 回归、生产前端浏览器验收、JavaDoc、差异及实际产物检查，沿用原版本任务升级至4.9.1-l。

## 用户原始要求

> v4.9.1-l：1. 插件配置在右侧额外开一个二级菜单 2. 插件管理的按钮颜色配置；向下对齐；没有本地配置、聊天配置的不进行展示按钮；关闭按钮使用开关式的按钮位于右上角，不是文字按钮；”启用意愿“ 与下方描述的距离过近 3. 插件对外展示尽量使用插件名字而不是id，但是允许使用插件名字和id进行筛选；4. 插件管理的位置位于管理最上层 5. 插件管理已安装功能使用按键弹窗形式，而不是下拉形式；不同领域（例如聊天命令、后台任务）之间分隔明确，标题颜色更分明，并且在弹窗中支持根据标题快速导航 6. 活动时间线显示”该功能所属插件已关闭。“，但是没有关闭的插件，疑似bug。7. 新增模型后LLM组件没有自动更新，此外如果默认模型改变其他使用默认模型的也跟着改变使用新的默认模型 8. 默认模型放置到第一个
