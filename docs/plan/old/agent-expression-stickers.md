# 拟人表达与表情包实施入口

日期：2026/11/03。状态：四批约定实现与离线验收完成，整体 100%，随配套规格及记录归档；本功能版本归属调整为 4.6.2-l，版本说明见[发布日志](../../changelog/4.6.2-l.md)。本进度只统计本计划，不计入已经归档的三层记忆计划、后续 4.7.0-l Web 控制台或未执行的真实环境验收。

## 已确认规格

- 拟人语气由人格与真实表达习惯驱动，允许减少闲聊标点、颜文字、口癖和语义分段；正式内容保留必要格式。
- 一条最终模型答案通过罕见占位符表示多段正文、等待、表情包和客户端表情，后端完整解析后有序执行，不逐段重新请求模型。
- 完整协议、协议内指令及内容处理器允许新增实现类，通过 Spring 服务/组件上的注解声明标识并由现有 scanner 注册；其他适合的策略/客户端/后端端口沿用相同机制，避免中央分支和扫描顺序覆盖。
- 表情包先提供类别，模型需要时取得选中类别全部可用 ID/描述，再在最终答案中引用；允许已有工具循环，最终回复只生成一次。
- 表情包必须独立发送，只可 plain/reply，不可附带正文或 at；客户端原生表情属于独立资源。
- 表情包在整个机器人实例共享，不绑定记忆 namespace、scope 或人格；已启用 Agent 的 scope 默认自动收集并限流。
- 一次视觉任务完成识别、描述、分类和收藏建议，严格区分表情包与插画；数量及容量由本地配置控制，支持按质量和他人使用频率优化。

## 边界及待实测参数

不启动真实应用、发送真实群消息或执行数据库迁移来完成设计；不新增外部项目依赖，不复制参考源码。实现继续使用专用 EasyData、原工具注册与执行设施，新增方法遵守中文 JavaDoc 和修改记录要求。

默认等待、采集限流、分析阈值、图量和替换权重均属于可调整的设计建议，需要真实体验验收，不是用户尚未回答的阻塞项。已确认共享和被动默认值写在上方，不再重复询问。

自主发言原零工具合同首期保留，仅复用文字节奏；若需自主类别选图，单独明确受限目录工具预算及协议。首期不额外建设 Web 页面、向量库、每轮人格改写模型或逐段拆句模型。
