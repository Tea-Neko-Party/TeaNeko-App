# 拟人表达与素材扩展的注解注册设计

功能版本：v4.6.2-l；本说明覆盖表达、素材与客户端扩展，不表示 v4.7.0-l 的 Web 管理适配器已实现。

日期：2026/11/03。状态：协议、指令、内容、素材后端及客户端的注解目录已落地，随实施计划归档。用户要求协议解析器能够通过新增 Spring 服务/组件类及声明注解扩展，其余适合的扩展点采用相同思路。本文件保存注册设计依据，当前 API 与使用说明见[表达模块](../../../src/main/java/org/zexnocs/teanekoagent/component/expression/README.md)；业务行为见[拟人表达](4.6.2-expression-specification.md)和[表情包](4.6.2-sticker-specification.md)，完成范围见[实施计划](agent-expression-stickers.md)。

## 统一流程

扩展作者实现对应接口，在 Spring 管理的类上添加职责注解，注解声明其稳定业务标识。宿主扫描注解与接口，校验后构造不可变注册目录；调用方按标识取得实现，不依赖实现类名、Bean 名或扫描顺序选择。@Service/@Component 或明确的 @Bean 负责创建对象，扩展注解负责说明身份，两者职责分开。

复用已有 [IBeanScanner](../../../src/main/java/org/zexnocs/teanekocore/utils/scanner/inerfaces/IBeanScanner.java) 的注解/接口扫描和代理目标类识别。需要懒注册时沿用原注解工具目录的 Bean 元数据与 Bean 名引用方式，真正使用时取得容器实例；不能为了注册目录提前启动模型工厂、后台任务、远程连接或读取业务数据。

注册时检查：

- 注解具有运行时保留和类型目标，标识格式有效、版本有效，实现类符合对应业务接口，注册的实际 Bean 可以通过该接口调用。
- 识别 Spring 代理的目标类元数据，但调用时保留原 Spring Bean 代理，避免绕过事务、插件拦截或生命周期。
- 同一个路由键只能有一个实现；冲突报告业务键、Bean 和声明来源并拒绝该目录注册，不用覆盖、@Primary 或优先级隐藏歧义。
- 同一旧标识不得被解释成不同语义；不兼容变化使用新协议版本。目录建立后不在每次请求重新扫描类路径。

注册目录只读并可查询描述。运行期插件逻辑启停仍由原 PluginRegistry 管理，不声称支持运行时加载/卸载 Java 类。每轮固定选中实现及所属插件版本，编译、交付及异步完成时复核；被禁用或换代的实现不能处理旧计划的剩余步骤。

## 协议与指令分别注册

下列协议、指令和处理器已加入源码并接入原生回复，素材后端及客户端也使用同一注册合同：

| 扩展层 | 声明与接口 | 注册键与职责 |
| --- | --- | --- |
| 完整回复协议 | @TeaNekoReplyProtocol(value="teaneko:expression", version=1) + IReplyProtocolParser | ProtocolKey(协议 ID, 版本)；解析完整回复正文并返回草稿，不发送消息 |
| 协议内指令 | @TeaNekoReplyDirective(protocol="teaneko:expression", version=1, value="STICKER") + IReplyDirectiveParser | DirectiveKey(协议 ID, 版本, 指令名)；解析一条指令及其正文为有类型的草稿 |
| 内容处理器 | @TeaNekoReplyPartHandler(value="teaneko:sticker", version=1) + IReplyPartHandler | PartKey(内容类型 ID, 版本)；验证/解析资源、生成历史投影及执行该类型的实际发送 |

例如一个标记 @Service 和 @TeaNekoReplyProtocol 的类实现 IReplyProtocolParser，即可声明一个协议；新增同一协议下的表情包指令，通过标记 @Component 和 @TeaNekoReplyDirective 的另一类实现 IReplyDirectiveParser。两者均由 scanner 发现并按注解查找，不要求改动宿主解析分支。

新信封使用公共的有界头部携带 protocol 和 v。宿主只读取头部及当轮标识，按精确 ProtocolKey 选择解析器，再由该解析器按精确 DirectiveKey 分派正文指令。未知协议、未知版本、缺少指令解析器或字段无效时整轮拒绝，不依次试跑所有解析器“猜一个能用的”。普通图文和旧 JSON 作为明确兼容协议进入相同目录；兼容入口的识别边界固定，不将已识别的错误新协议回退成普通正文。

协议解析器只负责语法，指令解析器只负责该指令的字段和字面正文；它们返回草稿，不能直接发送、下载、修改目录或解析真实目标。公共计划编译器继续校验客户端能力、实例 Feature、模式、数量、时限、ID 来源和授权，并固定最终不可变计划。

## 内容类型也允许新增实现

只把解析器改为可注册还不够：若最终内容仍是封闭枚举或 sealed 类型加中央 switch，新增内容会继续要求修改宿主。已实现的内容契约使用 ReplyPlans.Content，并通过内容处理器注册 payload 类型、版本和能力描述；文本、普通图片、表情包及原生表情均已使用该方式接入。

各注册项绑定明确的 Java payload 类型，在目录构造时核对解析产物与处理器声明一致；不使用任意 Map 作为所有类型的业务合同，不允许模型指定 Java 类名或触发 Class.forName。只有本实例允许且当前客户端支持的内容类型才进入可用协议说明。

IReplyPartHandler 可以处理本类型的资源验证、历史描述和平台编码，但真正的副作用由原统一交付边界调用：等待、原权限/目标复核、持久占用、真实平台确认、取消及资源释放仍由宿主管理。插件不能因实现一个发送器就跳过这些步骤。表情包禁止正文/at 混发等业务约束由公共验证和类型约束共同保证。

新指令的可用字段与模型说明也来自已注册且启用的描述，防止只注册了解析器却没有告诉模型其语法。描述仍经过宿主校验，注册不能向 Prompt 填入服务、凭据、真实授权对象或扩大执行能力。

## 其他扩展点沿用同一思路

| 领域 | 可注册实现及选择方式 |
| --- | --- |
| 人格表达与节奏 | 表达策略、节奏策略以稳定策略 ID 注册，由本地配置或 Feature 明确选择；同轮固定版本 |
| 图片理解 | IStickerAnalyzer 通过分析器声明注册，本地配置选择；模型路由和凭据仍统一由 model.yml 管理 |
| 收藏与淘汰 | IStickerAdmissionPolicy 通过策略声明注册；可替换质量/淘汰算法，硬容量、固定项和租约保护由宿主保留 |
| 文件后端 | IStickerAssetStore 通过后端声明注册，部署明确选择 local 或其他实现，禁止仅因发现一个 Bean 就改变实际存储位置 |
| 客户端图片/原生表情 | 已由 IExpressionClientAdapter、@TeaNekoExpressionClient 与 ExpressionClientRegistry 接通；按明确 client 注册，重复键拒绝，能力和不透明 ID 目录随本轮固定，详见[素材模块](../../../src/main/java/org/zexnocs/teanekoagent/component/sticker/README.md#扩展客户端编码) |
| 管理及观察 | 复用既有 ManagementResource、事件监听注解和插件归属，不另造一套平行扫描器 |

可组合策略按明确的阶段及稳定顺序执行，并说明是否允许短路；同优先级仍须确定顺序。互斥的实现用配置选一个，不能把“多个 Bean 存在”误当成按某种隐含顺序串联。具体注解名称与属性在实现对应功能时确定，只增加已需要的扩展点。

## Core、模块与运行时边界

Core 继续提供通用扫描、类型校验和必要的轻量键注册支持，不认识 TEXT、STICKER 或 Agent 人格。业务注解、解析接口、类型合同和注册目录放在 Agent/Client 对应模块，复用原插件归属与 Feature 选择；不建立携带所有业务对象的全局万能注册器。

发现一个 Bean 只表示可注册，不表示所有 Agent 自动获得它。宿主依据插件状态、实例 features、client 能力和本地配置生成当轮可用目录，解析与交付都不能超出该目录。注册信息不授予读取任意文件、跨区域操作或扩大预算的权限。

Spring 单例实现默认要求无请求级可变字段；身份、原文、当轮标识和控制通过不可变上下文传入，不把“当前用户/当前表情包”保存在共享 Bean。共享缓存需要明确边界与并发策略；扩展实现不关闭借用线程池、控制或连接。

只对真正存在多实现选择或新增类型需求的职责应用该模式。普通 DTO、内部辅助函数及仅有一个固定实现的简单协作不强行建立注解目录，避免以扩展性名义制造额外维护负担。

## 必要验证

实现时优先覆盖：Spring 代理下的注解识别与接口调用、重复键/错误接口拒绝、仅新增扩展类即可成功分派、协议与指令版本隔离、未启用扩展不可见/不可调用、禁用后的迟到执行拒绝。发送类扩展继续复用原权限、取消、回执和资源关闭验证，不为每个注册项复制整套测试。
