## 边界及设计

- 复用 Core Entity、ComponentKey、SystemPipeline；ECS 组件保存可序列化数据，System 由 Spring/scanner 管理，不序列化服务、线程或可执行闭包。
- 改造前仅有插件部分使用 ECS，主链固定处理人格、摘要、记忆引用和来源。本版将人格解析、历史提交、表达编译交给独立系统；宿主保留准入、模型循环及交付仲裁，原端口仅为历史宿主保留兼容路径。
- 业务存储和协议适配器保留原职责；组件的数据契约、参数、系统与注册声明集中分类，不把所有数据库实现混进 ECS。
- 缺少装配字段的历史记录按旧开关还原能力，不在读取时自动写回。显式新装配不隐式安装其他组件；必要依赖由声明校验，未知/重复/冲突项明确拒绝。
- 密钥只在受保护配置与实际认证边界使用，不进入 ECS 公共快照、Prompt、工具目录、活动或普通日志；Web 使用脱敏读取和明确替换。
- 不启动真实模型调用、不改真实数据库、不自动提交 Git，不修改用户的 gradle.properties。
