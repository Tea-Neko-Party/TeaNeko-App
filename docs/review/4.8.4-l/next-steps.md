## V484-D01：专用 HTTP 入口的扩展边界

普通管理能力已经能通过 `ManagementResource` Bean、类型化 DTO、宿主白名单和现有路由接入，不需要为每个新资源写 Controller。新增普通资源应优先走这条路径。

[WebSecurityConfig:77–126](../../../src/main/java/org/zexnocs/teanekoapp/web/WebSecurityConfig.java#L77) 对专用 API 明确列举路径，并最终 `denyAll`。因此新增独立 Controller 仍需改中央安全配置；`@WebManagedEndpoint` 只标识错误映射边界，不是自动授权声明。这个限制有安全收益，不应直接删除。

只有现有管理协议无法表达实际需求时，才考虑一次性建立由 App 定义、上层声明的启动期端点合同：校验 HTTP method、路径、角色、插件归属与冲突，保留精确允许列表、默认拒绝、会话、CSRF 和插件停用后的实际复核。不可按“所有 Controller”或宽泛路径自动开放权限，也不为假设中的路由需求提前实施。
