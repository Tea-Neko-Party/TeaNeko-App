# 模型连接中断调查

日期：2026/11/10；版本：4.9.0-l。用户反馈“当前使用非 deepseek 模型测试时，调用模型成功但是会报错”。本次确认并修正诊断误分类及检测提示边界；原聊天连接重置尚未复现，不能据此宣称故障已根治。

## 已核实事实

- 附件中的两个自动回复分别约在30.5秒、25.7秒失败，原因链为 `WebClientRequestException → SocketException`，根因为连接重置，未取得 HTTP 响应。中间成功的独立 LLM 交互使用不同请求 ID，不能作为这两个请求已经成功返回的证据。
- 实际模型路由使用 `openai` 适配器及 Responses 接口；型号名称自定义，不意味着使用厂商原生协议。失败记录包含16个工具、15条输入消息；成功的独立交互无工具、3条输入消息。诊断快照是应用模型端口的数据，不等于供应商最终处理的上下文。
- 用户先授权两次合成诊断，再授权追加四次。全部只使用新合成文本及虚拟工具，不发送聊天原文或业务工具声明，不执行工具。六次均返回 HTTP 200 和 `completed`。

## 本次代码修正

- `FailureDiagnostic` 区分连接建立失败与套接字/响应提前中断；后者提示远端结果未知。保留有界类型链、HTTP状态、位置和脱敏边界，不读取异常原文。
- 模型检测成功时明确说明只验证无工具短文本，未验证工具、长上下文及完整聊天流程。
- 补齐既有 `InteractionDiagnosticLogTest` 缺少的 `assertTrue` 导入；首次定向回归因此编译失败，修正后重新执行。
