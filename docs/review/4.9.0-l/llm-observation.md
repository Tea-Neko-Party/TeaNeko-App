# LLM 日志与记忆输入整理验证

日期：2026/11/08。三个实施闭环完成，3/3；[计划与用户原文](../../plan/old/4.9.0-llm-observation.md)。

## 日志中确认的问题

附件包含一次后台长期/风格联合学习和一次主动回复，不能按普通单轮用户聊天解释。首段应用输入约一万字符，四个中期片段同时携带简述、详细复述和19条原话证据；INFO 把这个对象全部打印为“本轮用户输入”。第二段当前发言在 `current` 和历史中重复，历史按保存序号倒序，与实际事件时间也存在交错。

首段输出的 `memories` 为空，`styles` 有一项；据此不能证明数据库中已经写入重复长期事实。能够确认的是输入材料复述、低信息社交样本进入提取，以及风格描述举出的字面例句不在引用原话中。处理范围以这些证据和真实源码链路为准。

## 实际改动

- INFO 保留单行键值摘要，标明请求、状态、耗时、响应模型、模型/工具调用数、已报告/估算/未知用量，以及应用端口与服务端未知边界。原内容开关继续控制 DEBUG 预览；默认1024字符预算，硬上限2048，每字段384码点。真实后端未启用 DEBUG 时不构造正文。
- 新增独立诊断 logger 和滚动 JSONL 文件，完整保留每次统一模型端口尝试的消息、System Prompt、工具/结构声明和响应，不使用预览预算截断。凭据、媒体链接、内联数据和供应商加密状态仍隐藏，超出脱敏安全处理能力时明确标记。文件不传播到根日志和网页采集；滚动为10MB、7天、归档总计100MB。
- 长期学习片段只携带简述，原话使用文本字典；完全相同的文本只传一次，各证据 ID、作者、时间、片段分别保留。独立真实发言仍可累积风格支持，来源及逐字引用仍在原事务中校验。提示版本升级后保留成功来源检查点，避免旧消息重学。低信息过滤补充纯“喵呜”“猫猫”类社交词，短事实和否定继续保留。
- 风格描述中的中文引号字面例句必须出现在本次引用中；合法的 quotes 不再能掩护描述中的虚构例句。真实例句正例与伪造例句反例均覆盖。
- 主动回复按原生消息 ID 排除已经采集的同一条当前发言，再按事件时间升序组织历史，并保留作者。相同正文的其他独立发言不会被误删。

配置与访问说明以[请求日志文档](../../development/web-console-agent.md#请求日志与诊断)为准。`diagnostic-log` 独立于摘要和预览开关，默认开启；只关闭 `include-context` 不会关闭诊断文件。
