# TeaNeko App 生产 MVP 评估标准

版本：4.8.6-l；日期：2026/11/06。用户确认的首发基线是**单实例、小规模受控用户**。本标准用于实现器交付与独立复核，当前结论见 [下一步实施](next-steps.md)，证据见 [验证记录](verification.md)。它不是评分表，也不是已取得的合规认证。

## 产品与部署边界

首发闭环是：管理员安全配置模型和聊天目标，真实用户能够完成对话，启用的工具/记忆产生可解释结果，故障时能判断结果是否确认、恢复数据并限制成本。网页档案是管理员模拟聊天身份，不是普通用户账号或多租户权限系统。

单应用、单数据库、包级模块化、现有 Vue/Element Plus 与声明式页面目录可以满足这个目标。必须说明容量、数据保留和恢复范围；暂不要求微服务、Kubernetes、Redis、向量库、独立前端权限系统或多个部署副本。新 Agent 最低装配为 LLM；记忆、人格、图库、社交和自主活动按产品用例启用。未启用功能不强求“每轮都执行”。

## 判定与证据

| 状态 | 使用规则 |
| --- | --- |
| 通过 | 明确范围内的合同与对应证据均满足；写明版本、配置和输入规模 |
| 部分满足 | 已有机制，但有适用路径缺口或只验证了一部分场景 |
| 未满足 | 当前源码或复现直接违背适用要求，附失败机制和最小证据 |
| 未验证 | 没有足够实际输出；不能自动算通过，也不能说已经发生事故 |
| 不适用 | 明确首发不提供或已关闭的能力，有产品边界依据；不能用来豁免通用认证、数据恢复等要求 |

证据分别标记：S 源码/配置，T 离线行为测试，B 真实浏览器及替身网络，E 真实部署/数据库/平台，L 代表性负荷与故障演练。它们互相补充：B 不证明后端安全，T 不证明 MySQL 锁性能，E 的一次成功不证明 L。历史报告可引用，但必须注明未在本轮重跑。

生产放行要求：首发适用范围没有未关闭的 P0/P1；关键事务、权限、结果未知恢复与资源终态有证据；数据库/发布恢复和关键使用流程完成实际验收。P2 需要修复、验证的限制措施或明确关闭对应可选能力，不能用总分抵消数据/权限缺口。P3 可登记后续，不阻止有边界的首发。

| 运维与交付 | 构建可重复，实际产物版本一致；状态、拒绝、延迟、队列、锁、成本可定位；备份/恢复与关闭有记录 | E/L + 产物清单 | 已有实施历史；本轮放行证据不足 |

## 扩展验收：把“只新增类/注解”变成可复核要求

记录 `M_core`（修改原核心/编排类数）、`M_ui`（修改既有 UI 组件数），另外记录新增类/声明、配置启用、测试及文档。这里的 0 表示不改稳定编排，不表示不需要授权、配置或依赖安装。

| 场景 | 期望修改成本 | 必须检验 |
| --- | --- | --- |
| 普通 ECS 组件 | 既有四阶段/字段类型内 `M_core=0, M_ui=0` | 新类+注解进入目录、持久化参数、真实系统执行；依赖环/越权键/重名拒绝，失败不发布补丁 |
| 注解工具 | 既有参数和上下文合同内 `M_core=0` | 单工具类可发现并实际执行；继承代理、client/requires、动态条件和异步结果有效；停用后不可调用 |
| 模型或配置适配器 | 现有合同内 `M_core=0` | 请求/响应规范化、凭据隔离、能力/预算/结构化输出与失败语义成立；不能只登记名称 |
| 普通管理资源/配置区 | `M_core=0`，通用字段 `M_ui=0` | 使用现有路由、DTO及白名单；撤权/版本/幂等/超时合同由实现履行 |
| 顶层页面 | 新视图+一个页面声明，既有宿主 `M_ui=0` | 导航、按需加载、草稿、轮询及离开守卫自动接入，后端仍独立授权 |
| 新协议/新阶段/新控件 | 允许必要的一次性合同修改 | 说明现有合同不足及消费者；不添加固定业务 ID 分支，不放宽默认拒绝 |

每次新增扩展选择一个真实纵向用例即可，不为了证明“可扩展”制造一批空类。新增扩展必须通过冲突、停用、失败发布和动态权限回归。工具已缓存的方法规格不等于可缓存当前执行资格。对第三方开放主动上下文来源前还须满足 E02。

## 容量与故障验收模板

下面是**建议的首发验收负载**，尚未实测达标，也不是用户已承诺的业务容量。先记录部署 CPU/内存、JVM/连接池、配置、输入长度、数据条数与模型，再由实际首发规模修订。不得把受控用户数直接当成并发上限。

| 阶段 | 建议输入/持续时间 | 要看什么 |
| --- | --- | --- |
| 基线 | 1 个活跃聊天、1 个管理员，固定文本/图片/工具请求，各至少 30 个样本 | 分开排队、模型、数据库和发送耗时，给样本数、P50/P95，不用平均值掩盖长尾 |
| 混合稳态 | 建议 10 个活跃目标、5 个管理浏览器按实际轮询间隔，开启首发所需后台学习/维护，30 分钟 | 控制台、前台对话及后台不互相耗尽；在途、连接池等待、锁等待、堆与任务年龄可收敛 |
| 过载 | 在已配置额度附近提高到约 2 倍输入，维持 5 分钟后恢复 | 明确拒绝、不无限排队、不丢未决状态；恢复后队列和资源回到合理水平，不补发未知结果 |
| 故障 | 模型/平台迟到或永不完成、一次数据库提交冲突、断网、撤权、空间换代及正常关闭 | 原编号可查；无重复计费/发送；事务失败不推进游标；实际完成前不提前释放容量 |
| 恢复 | 新库安装、旧数据升级、进程重启、从备份恢复 | schema/索引和应用版本对应；权威状态/防重/租约可解释，旧代次不复活；记录实际 RPO/RTO |

建议目标：纯本地管理读取在上述首发稳态下 P95 不高于 1 秒（不含模型探测/大导出），正常流量非预期错误率低于 1%；额度以内核心正确性错误为 0。它们是待确认的工程目标，不能据此宣称当前性能不合格。普通对话三十秒沿用已有产品目标，是否达到由固定供应商与输入规模的实际 P95 证明；若供应商无法满足，应明确调整产品承诺。吞吐扩容依据是锁等待、队列年龄和实测瓶颈，不是类数量或线程数量。

对全量任务和图库仍需专门观察：终态记录增长、清理游标、根锁竞争、磁盘配额及慢 I/O；短测未证明长期稳定。真实演练的执行步骤继续维护在 [部署清单](../../development/agent-deployment.md#实机验收清单)。

## 前端与 Java 的交付要求

前端按 [组件方案](frontend-components.md)交付 `ResourceStatePanel`、`OperationRecoveryPanel`、`ConfigFieldFrame`、`ResourceTabs` 或等价复用实现，包括 props/emits/slots、实际使用样例和异常状态。方案不要求新框架，也不要求把所有页面变成万能 CRUD。

无障碍以 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 适用 AA 条款为目标，页签行为参考 [APG tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。自动化与人工验证都要覆盖真实最终 DOM；Home/End 可作为项目增强要求，不冒充所有页面必需的 WCAG 条款。

Java 使用项目共享格式落实 [AGENTS.md](../../../AGENTS.md)；可在 [IntelliJ Java code style](https://www.jetbrains.com/help/idea/code-style-java.html) 中配置缩进、换行和单行保留策略。四空格、120 列软上限是项目规则，不声称是所有 IntelliJ 安装的默认值。先处理 [人工方法清单](java-structure-style.md#v486-j02应优先展开的具体位置)，不将词法命中数转成机械整改量。纯排版、职责提取与语义修复分别提供差异，行为变更只补能发现实际缺陷的测试。
