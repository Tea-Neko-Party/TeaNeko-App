# v4.9.1-l 输入校验诊断与用量提醒说明

2026/11/10 完成。用户报告自动回复在 `LLMInputValidator.validate:57` 失败，同时疑问累计用量告警阈值为何不同于模型输出额度。

## 定位与实现

原第 57 行合并检查图片角色和细节能力，抛出普通 `IllegalArgumentException`；安全日志不读取任意异常正文，因此只显示泛化的参数错误。该位置处于 HTTP 发送前，无法从旧日志还原具体消息下标、角色和细节值。

排查时本机模型路由使用兼容协议和自定义型号，但缺少图片能力声明；按该配置会得到空图片能力集合。已有文本调用成功不证明图片能力已声明，识图检测的临时试送也不修改运行模型配置。失败活动为 `AUTOMATIC_REPLY`，使用聊天 LLM；表情包组件的独立模型只影响采集。需要在实际选用路由中明确允许图片并保存应用，不能以其他请求成功代替当前配置核对。

新增 `LLMInputValidationException`，通过既有 `IFailureReason` 将首个失败字段、要求和实际结构传到日志、报告及模型提示。图片报告同时给出允许角色、允许细节和实际枚举；缺失消息、角色、内容及类型不匹配也提供结构对照。下标从零开始，未知类型原值、正文、图片 URL 和凭据均不公开。没有放宽图片准入或自动重发请求。

用量提醒使用 `tea-neko.agent.monitor.alert-tokens`，缺省回退 16384，与每次模型请求的 `max-tokens` 分开。日志中的 38397 是三次模型调用的累计总用量，包含输入及输出；达到提醒阈值不终止请求。日志已补完整配置键、累计口径及不覆盖输出额度的说明。用户同期把应用配置的提醒阈值改为 163840，本轮保留该值并核对已打包；未修改实际模型配置和凭据。
