# v4.9.1-l 后续环境验收

本版 8 项控制台需求、后续后台修复与独立视觉模型已完成实现及隔离验收，无已确认的实现待办。先阅读[视觉模型验收](sticker-models.md)、[控制台验收](README.md)、[后台修复验收](background-fixes.md)与[发布说明](../../changelog/4.9.1-l.md)，不重复进行已通过的普通回归。

追加的[识图接口授权与按钮间距修复](sticker-probe-fix.md)已通过真实 Web 安全链及隔离浏览器检查。[输入校验诊断与用量提醒](input-diagnostics.md)、[配置资源与图片处理边界](runtime-boundaries.md)、[结构化输出与有限纠错](json-correction.md)、[Gemini 原生代理适配](antigravity.md)及最新[自主时限与模型传输](model-transport.md)已完成定向验证，使用最后一份记录中的最新 JAR。前轮浏览器 API 替身通过不代表接口安全路由已被覆盖。

新增传输修复的环境检查：完整重启后，在实际代理核对 SSE 接口与首片时间，确认原长时图片、Schema 和工具续轮的完整响应。流式传输默认启用，可显式 `stream: false`；不自动试发另一协议。确认主动活动的候选总时限、模型阶段时限和目标发送队列时限符合部署需求，并观察新摘要中的失败阶段。当前本地 TCP/SSE 回归通过，不代表网关硬超时或网络中断已消除；本次未调用真实付费模型。

此前 Responses 的两次合成对照在 `strict=true` 时仍缺少必需字段，详见[历史诊断](json-correction.md#授权合成诊断)。随后按用户要求新增原生适配并切换本机 `gemini` 路由；Antigravity 分组使用 `/antigravity/v1beta/models`，严格 Schema 对照成功，普通 JSON 对照未补齐字段，完整请求历史见[原生验收](antigravity.md)。两者属于不同协议入口，不把旧结论外推到新路由。

需完整重启加载新适配器与配置，再确认真实图片、业务工具/签名续轮、记忆结构及真实耗时；本轮远端只测合成 JSON，没有测试 163840 输出额度或业务副作用。中长期生成成功但结构错误仍在原总时限内最多纠错一次；持续失败继续持久退避。已暂停批次需在工作区核对后恢复，真实记忆质量、远端纠错成功率与事务由备份实例另行检查。首轮原生 Schema 有一次传输失败，随后补测成功不等于原长时连接故障已经排除。

实际部署尚未执行：使用备份后的原实例配置启动 4.9.1-l，确认已有登录、插件目录及聊天选择；在真实聊天中确认活动时间线可读；模型文件应用后核对继承默认和显式路由的实际调用。真实模型调用、数据库写入及平台副作用另行明确安排，普通浏览器验收不触发这些操作。

本轮边界修复须完整停止旧实例后加载新代码。确认插件配置读取不再访问已停止的 Web 类加载器；实际采集遇到超限图时应得到 `FILE_TOO_LARGE`、大小对照和已释放预约，正常素材继续处理。再次发生交互预算拒绝时按新报告确认具体维度、实际上限和本次需求；旧“未识别异常”日志不能反推当时耗尽的维度。`image-input` 缺省仍沿用原模型能力规则，不自动授权未知型号图片输入。

后台实机检查：重启加载代码及本机 IDEA 原生访问参数后，确认旧队列在客户端账号就绪后恢复，已失败或已经开始的视觉作业不盲目重发。核对实际分层记忆时限是否有显式覆盖，观察模型真实耗时与 `memories/styles` 输出；若某批次已达到无效生成阈值而暂停，在工作区确认原因后明确恢复。增加默认时限与短字段提示不等于远端一定在时限内返回合规输出。

先前尚未复现的模型连接中断及其他环境验证仍见 [4.9.0-l 后续入口](../4.9.0-l/next-steps.md)。本版的模型目录与默认选择修正不构成远端连接故障已解决的证据。

独立视觉模型实机验收：在目标服务支持的 Responses/Chat Completions 路由上先保存图片声明，再分别点击组件和全局识图检测；检查实际颜色/形状结果。备份配置后验证首选失败仅接管一次、额度不足不调用备用，以及真实取消、插件停用、模型文件换代与临时文件释放。测试按钮会发起真实模型调用，可能计费；本轮开发只运行隔离模型和文件夹具，未消耗真实模型调用。
