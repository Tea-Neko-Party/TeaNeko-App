# v4.9.1-l 自主时限与模型传输验收

## 问题与处理

用户提供的两条失败属于不同请求。自主候选 `42ef426f-5365-378e-a6a2-01900de79892` 约 30 秒超时，源码存在覆盖排队、资料准备与执行的硬编码 30 秒控制；模型调用数为零不能单独证明具体卡在哪一阶段。自动回复 `95f57c00-096f-353e-a324-0e6ad0bf119c` 约 40.8 秒出现 TCP 连接重置，未取得 HTTP 状态和完整响应，日志不足以区分网关硬时限、上游中断或中间网络故障。OneBot 新连接日志本身不是错误。

已完成：

- 主动活动组件声明 `proactiveTimeoutSeconds`，默认 90 秒、范围 10–180 秒，旧装配自动采用默认值。触发票据按候选有效期授予，避免原 60 秒票据提前拒绝；普通触发保留原默认。候选继续受模型阶段和目标发送队列更短时限限制。
- 失败摘要记录请求、最后进入阶段、候选时限和耗时，移除重复“原因=”。超时后不消费迟到资料；插件停用继续等待实际工作结束，不重发已确认送达结果。
- Core 增加无缓存、无重试的 JSON POST / SSE 聚合契约，复用原阶段计时、取消仲裁及订阅释放。默认客户端禁用 TCP 中断隐式重发，普通 HTTP 显式重试声明保留。
- Antigravity 默认使用 `streamGenerateContent?alt=sse`，显式 `stream: false` 保留非流式方式；不会在失败后自动改协议或重发。完整 EOF 与候选终态都满足才交付工具/回复。原生签名与 Schema 保留，累计用量取最后快照，可见文本不因网络分片插入换行。终态后继续传输失败仍按失败处理。
- 非 SSE 响应返回可公开的类型不符说明；空流、未完成候选、身份变化、非法终态顺序及容量超限均明确拒绝。

配置权威说明见[原生协议](../../../src/main/java/org/zexnocs/teanekoagent/llm/instance/antigravity/README.md)、[社交插件](../../../src/main/java/org/zexnocs/teanekoplugin/agent/social/README.md)及[HTTP 生命周期](../../../src/main/java/org/zexnocs/teanekocore/api_response/README.md)。
