# Web 控制台体验与客户端设计

目标版本：v4.7.0-l，不归入 4.6.2-l 的表达与表情包交付。

日期：2026/11/03。状态：依据本次可视化需求形成的待实施方案，不表示已有网页、Web client、认证或热更新事务。总入口为[管理接口设计](web-management-api.md)，公网与登录约束见[安全设计](web-console-security.md)。本文维护界面、客户端映射和前端选型；后端共用合同由总入口维护。

## 已提出的需求与建议默认值

用户要求网页能够观察 Agent 操作、修改各聊天区域及本地文件配置并热更新、查看 Timer 与可筛选日志、指定已连接 client 执行指令，并以新建的真实 Web client 在网页聊天和模拟私聊/群聊。界面面向人组织，不要求直接展示程序实体或 scope 字符串。公网登录必须使用本地配置的令牌；没有配置时每次应用启动随机产生令牌，不能进入匿名模式。

建议前后端分开开发，发布时优先同源托管静态界面与 API；浏览器运行编译后的静态文件，运行应用无需常驻 Node 服务。初期为单实例、单管理令牌对应的本地管理员；未来多操作者再增加独立凭据与角色。Web client 是生产代码中的新适配器，不把测试目录中的 FakeClient 放入运行依赖。

## 前端选择

以下是推荐组合，并未安装依赖、锁定版本或创建前端工程。判断依据是配置表单、层级导航、日志列表、操作时间线和聊天界面的实现成本；不是通用框架排名。

| 组合 | 适合本项目的部分 | 取舍 |
| --- | --- | --- |
| Vue 3 + TypeScript + Vite + Element Plus，优先建议 | 配置表单、表格、树形导航、时间线等已有组件可组合使用，业务页面容易拆分 | 运行轨迹图与聊天消息仍需自己组织，不能把组件演示直接当产品界面 |
| React + TypeScript + Vite + Ant Design | 管理类组件丰富，适合较多定制交互及后续复杂可视化 | 需要统一状态与请求约定，避免为小页面重复组合工具 |
| Vue 3 + TypeScript + Vite + Naive UI | 沿用 Vue 方案，组件主题更便于统一定制 | 若已有 Element Plus 表单方案，不应同时混用两套组件库 |

上述组件依据分别见 [Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview)、[Element Plus 组件目录](https://element-plus.org/en-US/component/overview.html)、[Ant Design 官方说明](https://ant.design/docs/react/introduce/)及 [Naive UI 官方仓库](https://github.com/tusen-ai/naive-ui)。本期管理界面无搜索收录需求，首选静态 SPA；有服务端渲染需求时再评估额外服务层。锁定依赖时重新核验兼容性和维护状态。

路由、认证状态和必要界面偏好独立管理；后端快照、分页游标和资源版本由统一请求层管理。服务器数据不维护多份相互覆盖的状态。先提供表格和时间线，确有复杂关系时再加入节点图；大日志列表使用虚拟滚动，网络查询仍分页及限量。

## 导航与可理解的模型

建议侧栏为：总览、聊天平台、Agent、任务与定时器、运行日志、本地配置、指令台、网页聊天、插件、安全与会话。首页展示客户端就绪、活跃 Agent、待执行任务、近期失败和配置生效状态，并可进入对应详情。

聊天平台示例层级为 OneBot → 当前机器人账号 → 群聊/私聊 → 聊天对象。Web → 当前网页机器人 → 私聊/模拟群聊 → 会话。未实现管理适配器的平台可显示“尚未支持可视化管理”，不能因为存在 client Bean 就假设可枚举联系人或执行指令。

| 页面语言 | 后端映射与显示规则 |
| --- | --- |
| 平台，例如 OneBot、网页聊天 | 已注册管理适配器的 client 类型；显示中文名称、图标和能力，不以 Java 类名为菜单 |
| 机器人账号 | 实际 client 实例、自身平台 ID 及连接定位；不存在多账号路由时不宣称支持多账号 |
| 群聊，例如“开发交流群（123456）” | 适配器提供的群目标，映射已有 clientId/scopeId；名称未知则回退群号，不能编造名称 |
| 私聊，例如“小明（平台用户号）” | 已知用户及已有私聊配置定位；内部 UUID 放入高级详情 |
| 聊天设置 | 字段中文名、说明、默认值、当前值、来源、生效状态；内部字段名可在高级模式查看 |
| 记忆空间 | 实际 namespace，明确哪些聊天共享；共享不因界面按平台分类而消失 |
| 人格及聊天习惯 | 该聊天目标绑定的人格及观察结果；默认按原 scope 独立，不误标为整个平台人格 |

前端只提交服务端发出的不透明 targetRef；服务端通过管理适配器映射到当前真实目标并重新授权，不能信任浏览器提交的昵称、selfId、UUID 或拼接 scope 字符串。targetRef 只是定位，不能充当权限票据。详情按需显示内部映射，普通用户无需理解 scope。

管理适配器采用 ClientManagementAdapter 接口、建议注解 @TeaNekoClientManagement(clientId,version)、Spring Bean 与 scanner 注册目录组合。注解声明实际 clientId，重复键或不支持版本明确拒绝；@PluginOwned 和插件启用代次继续生效。适配器负责平台名称/能力、账号与目标查询、内部映射、就绪检查和明确支持的命令描述。新增 client 只需贡献适配器，不在中央 Controller 持续增加 instanceof 分支；发现适配器不代表当前连接可用或当前主体有权限。

现有群 scope 按 client 和群号构造，私聊 scope 使用项目用户 UUID；后者不天然包含 client 或账号。因此相同用户映射可能指向同一配置。页面须显示“共享配置”标记及影响范围，多个入口修改同一资源仍使用同一 revision，不能假装已完成数据库隔离。此阶段不为配合导航擅自改动既有 scope 编码。

联系人目录合并已知持久化目标、运行期发现及适配器明确支持的平台查询，标记名称来源和更新时间。客户端断线后仍允许查看已知对象及修改本地持久配置；依赖平台操作的指令与发送则停用。不把“数据库中已知群”标成“该机器人当前全部群”。

## Agent 操作视图

列表按当前活动、聊天目标、Agent 定义和时间筛选。一次活动以 requestId/runId 贯穿阶段、模型请求、工具、记忆、发送和日志；界面可用如下可理解的过程名：

接收消息 → 整理上下文与读取记忆 → 请求模型 → 调用工具（可能多轮）→ 生成回复计划 → 等待并逐条发送 → 后台学习或完成。

这是对实际节点的投影，必须保留稳定内部阶段 ID，并允许分支、循环及未知节点；没有埋点不能显示“已经读取”或精确耗时。异步启动、执行器任务结束、实际模型/发送完成分开展示。无总量时显示当前阶段与耗时，不编造整体百分比。

工具参数和结果按权限脱敏、截断并标记；默认显示名称、用途、耗时、终态和安全摘要。模型输入、聊天、记忆、日志均属受保护内容；不展示或索取模型隐藏推理过程。失败区分未发起、明确失败、取消请求和结果不明。已发出的分段保留真实确认，停止按钮不会承诺撤回已发送内容。

记忆页按短期/中期/长期、人像与人格拆分，展示时间、来源聊天及共享范围，编辑或遗忘走原用例的版本/代次保护。表情包页直接复用已经实现的四项图库管理资源，不另造目录 Store。

## 聊天区域与文件配置

区域设置按“Agent 与回复、模型与工具、记忆、人格与表达、素材、任务”等业务分组。未配置、继承默认、显式覆盖分开显示；保存前提供变更预览和共享影响。普通字段走原校验器及原子版本更新，namespace/人格绑定走专用操作。网页、命令和后台更新必须在同一权威提交边界仲裁。

本地配置按用途显示，例如模型、表达节奏、素材库、调度、安全，并映射已注册 FileConfig。普通文件可提供结构化表单与受限 YAML 编辑；路径由宿主注册，禁止任意读写文件。配置能力描述每个字段的可写性、敏感性、校验和应用方式。

保存流程为：读取原始文档及版本 → 编辑 → 解析/环境占位符/业务校验 → 比较预期版本 → 原子替换文件 → 发布新配置代次 → 等待相关应用方确认。文件和运行状态不是同一事务，页面应分别显示“已保存、应用中、已生效、应用失败、需要重启”，不能在写入成功时就显示全局热更新成功。

原始 YAML 树和已解析运行值分开保留；只改指定节点，保留未改的环境占位符，不用展开后的 DTO 覆盖整份文件。注释/排版保留由选用编辑方案明确支持，不能假定现有 YAML parser 自动保留。敏感文件使用专门受限字段视图，密钥只显示已配置/未配置；保留、替换、清除是独立操作，脱敏占位符不能当真实值写回。网页不能读取服务器环境变量值。

支持动态应用的配置热更新；端口、监听地址、线程池等只有在所属模块明确实现时才标可热更，否则提示需要重启。更新模型或后端配置时遵守原在途请求快照和代次，不让旧请求拼接新旧凭据或资源。应用失败保留实际磁盘/运行状态及安全诊断；回退也必须比较版本，不覆盖他人后续修改。

## Timer、日志与实时刷新

任务页面提供“调度规则”“待执行计划”“正在运行”“历史结果”视图，区分 Core Timer、持久 Agent 计划和单次执行。显示中文名称、来源插件、周期/时区、下次预计触发、当前活动、最近结果与 supportedActions。FixedRate、FixedDelay、SmartRate 和 Cron 的计算语义保持真实；不为未知下一次时间伪造倒计时。

取消未来计划、请求停止当前活动、暂停规则分别表达，只显示后端真实提供的动作。系统维护 Timer 默认只读，不提供通用“任意修改周期/立即执行”按钮。详细运行可关联 Agent 操作与日志。

日志按时间、级别、模块/插件、client、聊天目标、Agent、requestId、runId、关键词筛选，具备暂停滚动、分页、上下文查看和受限导出。没有结构化字段的旧日志标为未知，不能通过脆弱文本解析冒充精确筛选。初期增加有界脱敏实时窗口；历史使用滚动结构化文件或明确实现的后端，不假定 ILogger 已经提供日志数据库，不把所有日志写入 EasyData。

实时更新首选同源 SSE，写操作仍使用 HTTP；聊天输入也可 HTTP 提交、SSE 接收消息与交付回执。需要双向连接再使用 WebSocket，不因“聊天”默认引入第二套消息总线。断流、窗口过期、进程重启显示重新同步，慢浏览器不能阻塞业务线程。统一实时合同见总入口。

## 指令台与客户端就绪

指令台用于执行 TeaNeko 已注册且被该管理适配器明确允许的命令，不是操作系统终端或任意 OneBot JSON API。操作者先选平台、真实账号与聊天目标，再选择命令或输入文本；展示 @Description 用法、参数和预计影响。平台原始 API 如后续需要，应另外提供类型化动作和独立权限。

执行者始终是已认证的管理操作者；目标聊天是执行环境，不代表操作者冒充该群成员。新增可信 CONSOLE/MANAGEMENT 来源及显式权限映射后，复用原解析、client/命令限制和业务 Stage。浏览器不能提交 senderId、OWNER/DEBUG 权限或假造原生事件。强依赖原始平台消息、引用或成员身份的命令默认不可执行，须有专用管理适配后才开放。现有 NativeCommandBridge 的 USER 原生来源约束不得以伪造消息绕过。

所有面向其他 client 的网页指令都要求当前真实连接可用：适配器启用、传输已连接、身份已确认、目标可定位且平台就绪。分别展示“未启用、未连接、已连接待身份确认、可操作、状态不明、账号冲突、停止中”；页面缓存不是执行许可。提交和实际副作用前再次复核 connectionEpoch/账号，断线或换号使旧排队请求失效。断线后不静默换连接、不自动重试可能已经发生的动作。

现有 OnebotClient.isRunning() 只表示生命周期，OnebotIdService 的缓存 ID 也不能证明仍在线；需补连接快照、身份绑定和断开失效。当前发送遍历所有 session，不能将多条连接包装成已支持定向多账号。首期要求唯一明确账号及可操作连接；多连接归属不明时拒绝指令。真正多账号执行要先完成按账号/连接定向路由，前端模型可预留 accountRef。

命令结果在原 CompletionStage 真正结束后标完成；输入已受理、平台消息已确认分别显示。为操作保留 operationId、操作者和目标，发生未知结果查询原操作，不换 ID 猜测重发。输出可在指令台展示；向真实聊天发送必须是命令已声明的行为，界面明确标识目标。

## 新建 Web client

新增生产级 WebTeaNekoClient 及对应工具箱、消息适配、管理适配和必要表达客户端，独立 clientId。使用已有 TeaNekoClient 注册和真实消息/命令/Agent 入口，不给 Controller 单独创建一套模型循环；消息回到网页时走同一发送守卫和逐段交付账本。

服务器管理网页用户档案、虚拟群、群成员、机器人身份和消息 ID，支持私聊、群聊、昵称/群昵称、提及、回复以及受限图片。默认发言档案来自会话；允许管理员选择的模拟成员由服务器检查群关系和创建记录，不接受浏览器自行决定 UUID/权限。模拟成员的权限由专用管理操作设置，与网页管理员权限分开。

每条消息标明来源是 Web client；私聊沿用自动触发，群聊可以提及机器人或输入命令，支持模拟不同成员。网页的 @机器人必须映射该 Web 机器人自身身份，不让模型猜未知用户。图片等媒体使用认证受控资源和已有模型图像端口，不接受任意服务器路径或远端抓取地址。

模拟区域、档案和真实 OneBot 身份不混用。记忆 namespace 仍遵守项目默认共享规则，不悄悄修改默认隔离；界面醒目标注当前共享空间和可能影响。演练者可以明确新建并绑定测试 namespace，隔离学习与持久记录；人格仍随各真实映射目标独立。是否写历史、自动记忆和画像均显示当前开关。

浏览器断连不自动注销整个 Web client，也不等于删除群和历史。消息受理、持久化、投递网页、前端可选确认分开：发送返回的消息 ID 应对应服务端已可靠记录的消息，不虚构对方已读。重连依消息游标补齐已提交分段，重复页面不再次触发 Agent 或重复发送。消息和运行结果均经服务端授权，附件、导出及实时订阅不能绕过会话检查。

## 本阶段边界

本轮只有设计，没有修改运行代码或发布公网入口。前端组合、默认页面和具体端口名均为建议；实现批次及可用程度由后续实施计划记录。先完成登录与客户端/区域配置的可用闭环，再接运行观察、文件配置、Timer/日志、指令台和完整 Web client；每批交付实际页面、接口与必要高风险验证，不按文件数量拆进度。
