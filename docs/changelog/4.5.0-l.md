# TeaNeko App v4.5.0-l

## 版本重点

建立新版 Agent 运行体系，将模型交互、会话、工具、记忆、人格和平台适配按职责分层。提供可实际接入的图文对话、记忆管理、后台学习、任务提醒与自主行为，并统一异步完成、权限检查及数据版本约束。

## 新增功能

### Agent 与模型交互

- 提供独立 Agent 定义、实例注册和轮次执行，支持显式服务调用及按客户端、作用域隔离的会话。
- 支持文本、图片和混合消息输入，以及图文回复计划；回复目标、顺序和真实发送回执由平台适配层处理。
- 建立统一的有限模型与工具交互，支持模型、工具次数及总时限等预算，子步骤共享原轮次预算和取消链。
- 接入 OpenAI Responses、DeepSeek、Kimi 等模型适配，统一消息、工具 schema、响应、用量与错误语义；按模型能力检查实际输入。
- 提供显式多 Agent 顺序协作，保留来源与交接校验，共享父预算；实例由宿主选择，不自动授予其他实例的业务权限。

### 记忆、画像与人格

- 新增长期事实、用户画像、相关记忆检索和短期会话窗口；长期事实按 namespace 共享，画像保留用户主体，历史查询保留作用域边界。
- 提供本人事实新增、记忆查询、画像及历史工具，返回结果携带来源、版本、时间与完整性信息，支持有界扫描和输入裁剪。
- 支持空间绑定、切换和 reset；clear 通过 generation 换代立即隔离旧数据，阻止旧轮次和后台任务回灌。
- 提供 DEBUG 记忆维护：分页、导出、编辑、锁定、克隆、清空及分批旧代次回收；写入使用预期版本和持久化操作回执。
- 分离基础人格、人格补正与用户画像；支持人格切换、补正 key 管理、备份、克隆、编辑、锁定与撤销，并同步相关会话引用。
- 提供后台摘要及补正学习；前台交付与后台任务各自保留执行、失败及版本校验边界。

### 工具、Skill 与任务

- 新增 `/agent` 显式对话和状态入口，接入原 `/cfg` 群组配置及真实权限体系。
- 提供受原生命令权限保护的命令工具，沿用实际消息来源、参数解析和反馈等待，并以持久化账本防止重复执行。
- 支持本地 Skill 目录、作用域选择、按需加载和 DEBUG 重载；Skill 依赖工具必须已经授权，目录重载后旧快照需重新复核。
- 提供文件、代码执行和知识检索的受控后端接口及工具适配，后端由宿主显式提供。
- 支持持久化提醒任务、查询、取消和重启恢复，以及有界的自然语言任务创建；结果区分明确完成、拒绝及副作用不明。
- 接入定时发言与接话候选，统一处理准入、静默、冷却、退避及真实交付记账。

### 平台与监控

- 接入原生消息采集和图文消息，统一处理 `reply`、`at`、`plain` 等回复形式，保留原平台目标及发送顺序。
- 提供新版进程内 Agent Client、Toolbox、三类 Sender 和响应接口，保留 `teaneko-agent` 客户端标识。
- 新增脱敏轮次报告、用量统计、阈值告警及冷却机制；供应商报告用量、估算用量与未知用量分别记录，模型成功和平台发送结果分别统计。

## 架构与配置调整

- Core 增加类型化组件、不可变实体快照、组件补丁及依赖可校验的 System 管线；Agent 在既有执行、任务、事件及定时器设施上组合业务。
- 所有命令处理方法统一返回 `CompletionStage<?>`，通常为 `CompletionStage<Void>`；调用方等待实际业务和反馈结束，异步异常沿完成链传播。
- 新版 Agent 数据统一写入 `tea_neko_agent_data`，Store 通过 `TeaNekoAgentEasyData` 及事务 DTO 访问，沿用原行锁、重试与缓存机制。
- 模型默认路由、模型参数、`api-key`、连接设置和 `metadata` 统一放入 `config/agent/model.yml`；`main-config.yml` 保留 Agent 本地总开关。
- Core YAML 文件配置支持 `${变量名}` 与 `${变量名:默认值}`，在解析 YAML 结构后展开字符串值；必需变量缺失时加载失败。
- 敏感文件配置的普通导出和加载失败日志不暴露密钥；加载不自动写回，显式保存使用当前对象值。
- 增加保留 `-l` 后缀的版本升级、Git 预览、选定内容提交及标签入口；复用原三段版本号，不自动推送。

## 兼容性与升级说明

| 变化 | 升级要求 |
| --- | --- |
| 运行基线调整 | 使用 JDK 25、Gradle Wrapper 9.8.2 和 Spring Boot 4.1.2，重新编译依赖本项目的代码。 |
| 命令返回类型变化 | 原 `void` 命令改为返回完整 `CompletionStage`，反馈发送也应纳入返回链；禁止启动后台工作后提前报告成功。 |
| 旧 Agent 实现退役 | 旧 `teanekoagent_old` 源码及专属测试移除；内部集成使用新版 Client、Sender 或直接服务接口。 |
| Agent 存储统一 | 按上线前新表方案交付，不提供旧 Agent 数据自动迁移；旧表不会被自动清理。 |
| 模型配置合并 | 将旧 application 供应商密钥、地址、路径和默认路由移入同一 `model.yml`，不再依赖旧配置回退。 |
| 环境占位符保存语义 | 显式写回可能保存展开后的环境值；需要保留占位符模板时直接编辑 YAML。 |
| scope 与管理权限 | 先登记并启用目标 scope；空间绑定、维护、导出和人格管理继续按各自 OWNER/DEBUG 约束执行。 |

## 验证与交付边界

- 交付记录包含 98 个离线测试类、962 项用例，其中 961 项通过、1 项真实模型测试跳过；完成强制编译、普通及可执行 JAR、资源和 JavaDoc 核对。
- 真实 MySQL、OneBot、模型连接、完整启动和长期性能需按部署清单验收；尚无实机证据确认普通对话达到三十秒目标。
- 文件执行环境、代码隔离和完整文档索引由实际后端负责；本版提供端口与适配，不默认开放宿主文件或 shell。
- 取消不表示已经回滚外部副作用；处理阶段结束不等于业务成功，模型成功不等于平台已经发送。
