# v4.9.1-l（待发布）

本版改进插件管理与模型配置体验，并修正后台素材采集与记忆整理，不调整数据库表、插件 ID 或已有聊天装配。

## 插件控制台

- 插件管理移到“管理”组最上方，插件配置在主侧栏右侧展开独立二级导航，手机使用抽屉内的二级菜单。
- 插件卡片使用右上角启停开关，继续先预览再确认；启用意愿与实际状态分开显示。配置入口仅在有对应功能时展示，按钮使用当前主题色并向下对齐。
- 插件优先显示名字，名称和 ID 均可筛选；稳定 ID 保留用于准确定位。
- 已安装功能改为弹窗，聊天命令、后台任务等领域使用清晰分组与标题，并提供快速导航。
- 修复系统活动时间线被错误当作已关闭插件而无法读取的问题。

## 模型配置

- 模型页新增、编辑、删除及修改默认模型后，保存成功自动应用该版本；应用失败与未确认操作如实显示并保留恢复入口。
- 模型应用后刷新 LLM 选择目录，重新打开参数页及前台轮询也会同步其他会话变更，保留未保存的装配草稿。
- 继承默认模型的聊天从新请求使用最新默认路由；显式路由和聊天私有模型保持原选择。
- 默认模型卡片置顶，LLM 下拉保留继承项首位、具体默认路由紧随其后；编辑删除仍对应原文件条目。
- 输入校验错误现在报告字段位置、允许的图片角色/细节与实际结构，明确发生在发送前；不输出正文、图片地址或凭据。累计用量告警注明阈值配置键及统计口径，明确不限制调用、不覆盖模型输出额度。
- 模型与工具的预算不足现在报告资源维度、实际上限、占用量、剩余量和本次需求，不再显示“未识别异常”；原预算和副作用前校验保持生效。
- 新增系统原生 `antigravity` 适配器，使用 Gemini 原生生成接口，支持图片、工具续轮/思考签名及 JSON Schema；配置目录自动显示，无需安装业务插件。可与既有 Responses/Chat Completions 并存，不自动换协议。
- Antigravity 模型选项使用随程序交付的官方 SVG 图标，通过适配器元数据进入通用模型目录，页面不依赖外网加载图标。
- Antigravity 默认以 SSE 接收并聚合完整响应，保留 Schema、工具及思考签名；分片不执行工具，断流或缺失终态明确失败。显式 `stream: false` 保留非流式路径。HTTP 客户端关闭 TCP 中断隐式重发，防止远端结果未知时重复提交；不保证消除网关自身超时。
- 原生代理配置填写根地址和模型集合路径；普通入口为 `/v1beta/models`，分组专用入口可用 `/antigravity/v1beta/models`。路由 ID 与模型输出额度可以保留，密钥只通过请求头发送。完整参数见[原生协议说明](../../src/main/java/org/zexnocs/teanekoagent/llm/instance/antigravity/README.md)。

## 后台采集与记忆整理

- “主动活动”组件新增候选总时限，默认 90 秒、范围 10–180 秒，替代原硬编码 30 秒；触发票据同步有效期，仍受模型阶段及目标队列更短时限限制。失败摘要包含请求、阶段、候选时限和耗时；超时和停用保持真实排空及发送前复核。

- 旧表情包作业在客户端账号未就绪时保留队列并延后复核；来源采集关闭或处理中资格变化显示具体原因，继续完成资源清理，默认不自动重发已开始的视觉请求；明确配置备用模型时按下述有界规则处理。
- 超过 `max-file-bytes` 的图片按 `FILE_TOO_LARGE` 正常拒绝，INFO 记录大小与上限，释放暂存和容量预约，不进入视觉分析。默认文件上限仍为 6 MiB，不自动放宽。
- 结构化模型指令从 Schema 自动保留简短的顶层字段名，减少兼容服务返回字段别名。严格校验保留，错误输出不会自动改写后存入记忆。
- 中长期记忆遇到成功响应中的 JSON 结构错误时，向模型反馈具体字段错误和完整 Schema，最多纠错一次；共享原批次时限与预算，每次复核完整输入和准入。持续失败不提交事实、风格或水位，沿用持久退避；已暂停作业需在工作区确认后恢复。网络错误、拒答、截断、取消和证据关系错误不触发即时纠错。
- 分层记忆整理默认时限由 45 秒改为 90 秒，显式配置和 120 秒上限保留；超时、无效输出仍不推进水位，沿用原退避及暂停恢复。

## 表情包独立视觉模型

- 表情包组件默认跟随聊天 LLM，也可选择已有模型或填写独立私有模型；选择不改变聊天使用的模型。
- “插件配置 → 表情包识图模型”提供全局备用，新增 `config/agent/sticker-model.yml`。主模型不可用或请求报错后最多使用一次备用；实际结束、权限及版本复核、两级采集额度与共享预算仍生效。取消和资格失效不会触发备用。
- 组件与全局设置均可检测已保存模型，发送内置 96×64 合成测试图，正确识别画面才判成功。检测无工具、不发送聊天、不采集素材、不自动调用备用。
- 修复识图检测接口未声明安全路由导致的权限拒绝；两处检测由插件精确声明 POST 入口，继续要求登录、防伪及资源授权。增加全局模型选择栏与保存、刷新按钮之间的间距。
- Responses 及兼容 Chat Completions 新增可选 `image-input` 声明，自定义视觉型号可明确允许图片；省略沿用已知型号判断。检测成功不会自动修改模型文件。
- 私有连接及 metadata 不进入运行组件，页面沿用密钥保留；新增文件标为敏感，仅通过明确字段规则编辑。旧非空 `stickers.yml model-id` 在未设置新备用时继续作为兼容备用。

## 升级与验证

修复文件配置模板依赖线程上下文类加载器的问题；首次初始化和网页文档读取均使用配置类型的类加载器，避免 Web 容器停止后异步线程访问旧模板入口。该问题与 `image-input` 是否填写无直接关系。

普通本地配置仍需分别保存和应用；模型页保留“应用磁盘配置”处理外部文件编辑或应用恢复。未改写 model.yml 路径、凭据与聊天配置。验证范围及未执行环境验收见[本版验收记录](../review/4.9.1-l/README.md)。尚未发布、创建标签或部署。
