# v4.8.2-l

发布日期：2026/11/05，Git 标签 `v4.8.2-l`。

## 模型配置

- 新增模型、完成编辑和确认删除直接保存磁盘，无需再次点击外部保存。保存与运行应用继续分开；未改密钥、环境模板和未知字段保留，保存前说明 YAML 会重排且不保留注释。
- 卡片提供真实模型检测：初始或编辑后显示“未检测”，完成后显示成功或失败原因。检测使用已保存版本，不读取旧运行缓存冒充结果；版本或权限变化后拒绝迟到结果。
- HTTP 401/403/404/429、连接、DNS、HTTPS 与超时提供固定说明，未知错误显示代码位置，不导出凭据或供应商响应正文。检测会产生一次真实调用费用，最长 60 秒、实例最多四个并发，使用配置中的完整输出额度。
- 服务地址与接口路径直接可见；修复私有模型协议下拉列表图标超高、文字拥挤的问题。
- 模型弹窗先显示协议、服务地址与接口路径，再显示路由和其他参数；API 密钥操作不再使用“秘密”字样。
- 缺少后端环境变量时直接说明变量名和启动环境要求，保留原文件；修复 HTTP 400 校验失败后仍锁住表单的问题。变量就绪后可继续保存，环境模板不被展开值覆盖。

## 网页聊天

- 入站异步失败不再被笼统回执吞掉：记录操作编号、实际阶段及脱敏根因；高级回执可查看进行中阶段，失败提示在简洁模式也可见。
- 聊天配置改为可展开卡片，每张卡片独立应用、登记或取消登记，切换保留各自草稿；工作区选择其他聊天改用返回图标。

- 聊天室顶部新增当前发言档案的权限下拉，确认后切换 MEMBER / ADMIN / OWNER，复用原成员事务、版本校验和操作编号，不清除输入草稿。私聊只更新原有唯一成员，不允许新增、替换或移除身份；网页角色不等同于网页登录管理权限。
- 当前发言档案的消息靠右，其他成员与 Agent 靠左。
- 房间目录新增垃圾桶按钮，经一次不可恢复确认删除该房间、消息及附件；保留用户档案、聊天配置和共享记忆，旧来源不能通过迟到发送恢复房间。
- 简洁模式隐藏详细操作回执，保留正常指令输出和必要错误提示。
- 修复正常发送时短暂闪出“原请求结果待确认”的问题；只有实际失败才展示恢复入口，仍保留原编号防止重复发送。

## Agent 失败说明

- 修复模型请求前反复全量扫描类路径，导致普通聊天和 `/agent chat` 长时间无回复或超时的问题；配置类型在当前容器只发现一次，配置值热更新、权限及模型代次复核继续保留。
- 模型配置样板及凭据输入扩展也改为单次发现，页面读取仍按当前模型注册与插件启用状态筛选。
- LLM、表达编译及邮箱交付贯通安全诊断，后台与用户提示保留具体原因；上下文原始失败不再被后续执行停止覆盖。
- 会话准入观察、记忆与人格准备、窗口和排队策略加载失败同样保留安全异常类型及代码位置，不再只显示通用配置错误；首次终止和后继请求推进保持原规则。
- 默认通过原发送器回复失败原因，可在聊天设置关闭“失败原因回复”，或执行 `/cfg set agent failureReplyEnabled false`。取消、撤权、关闭仍禁止迟到提示；发送器失败不触发重复补发。
- 修复失败回执策略传入配置注解而非管理器实例，导致超时提示再次抛出“没有 ConfigManager 注解”的问题；回归覆盖真实配置服务转发。
- 拟人协议优先允许普通正文，分段时提供完整逐行示例；头部、当轮标识和 END 错误分别说明。控制行边缘空白可接受，不完整信封及非法指令仍拒绝执行，不将控制文本直接当答案发送。

## 扫描与配置查询

- 底层类与 Bean 发现只在创建、初始化或显式重扫中执行；业务查询读取专用目录，规范同时覆盖目标类型解析、Bean 定义遍历及方法目录发现。
- 文件配置类型新增专用 `FileConfigScanner`；原文件查询服务提供 `withRuntime()`，模型参数与凭据校验复用原发布锁和缓存版本，不再为查询创建文档或读取模板。普通查询继续使用 `get()` / `requireCurrent()`。
- 定时器页面、表情包采集资格与重新分析、工具说明目录改读缓存。任务、客户端连接、插件启用及权限状态仍实时检查。
- 命令说明与指令台复用已登记类型说明和方法；前缀与正则目录完整构建后一次发布，失败重扫保留原目录。
- 模型路由、模型表单、聊天配置、文件配置管理和网页房间准备目录在初始化阶段发现；查询不再触发首次扫描或失败重试。相关目录重扫失败保留旧缓存，首次初始化失败明确报告未就绪。
- 重载服务保留初始化失败对象的登记，修复声明后可通过显式重扫恢复，无需由每次聊天或页面请求重复发现。

## 升级与验证

- 默认运行环境统一为 `prod`，`bootRun` 由后端同时提供网页与 API；本地联合开发显式选择 `dev,web-dev`。Web 模板默认启用并信任本机开发代理，已有配置不自动覆盖。
- README 改为构建、控制台、客户端与开发入口，详细参数集中到文档导航；新增构建指南，移除失效交流群与过期操作说明。
- 机器入口支持同机或 Docker 内网直接 WS，继续执行机器令牌及换钥后的连接撤销；不依赖回环 IP 判断同机，后端端口访问范围由监听地址、Docker 网络与防火墙控制，网页管理继续要求 HTTPS。
- 客户端页分别展示本机 WS 与公开 WSS 地址。公开 WSS 可使用任意有效独立端口，复用公开来源配置并由 TLS 代理实际监听；部署说明补充 7443 示例和开发端口调整。
- 客户端页展示完整 WSS 连接地址、对外端口与后端代理端口；令牌用眼睛查看/隐藏，下方单独修改，离页清除显示。
- 新增 `tea-neko.websocket.port`：默认 `0` 共用后端端口，非零增加本机 HTTP 代理监听；开发代理自动跟随。`tea-neko.websocket.public-origin` 可声明独立公网 WSS 地址，仍需配置 TLS 代理，修改后重启。

本机开发新增 `npm --prefix frontend run dev:certificate`，只导出开发公钥证书，便于机器客户端信任 WSS；文档补充 HTTP/TLS 端口混用和自签证书的处理步骤。

无需数据库迁移，已有聊天的失败原因回复默认开启。重新构建并重启后端、刷新网页后生效；Git 标签发布不代表已完成实际部署或供应商联调验收。
