# v4.7.2-l

状态：功能实现与离线验证已完成，尚未确认发布。

本版本统一模型输出额度和上下文准入，修复记忆整理因隐含 token 限制而无法完成的问题，并完善网页聊天的创建入口与类型识别。模型配置需要补充上下文容量，升级要求见下文。

## 模型输出与预算

- 中期压缩、长期记忆整理、内存会话摘要、人格学习、表情图片分析和主动发言统一使用所选模型的 `max-tokens`，移除各业务额外设置的输出 token 常量。
- 预算层完整预留“输入估算＋模型配置的输出额度”。任一级显式总预算不足时在请求前拒绝，不再自动降低输出上限，避免结构化生成被隐式压缩输出空间。
- 移除后台生成的固定 `16384`、`8192` 等隐含总 token 配额。摘要与人格学习的 `max-total-tokens` 仍可显式配置，原有父子预算、并发预留、实际用量结算及超额后停止规则继续生效。
- 模型调用次数、工具次数、超时、输入字节容量、摘要字数和候选字段容量继续独立约束；取消业务 token 常量不会放宽持久化数据契约。

## 模型上下文准入

- 模型配置新增必需的 `context-window-tokens`，由部署者声明当前模型的真实上下文总容量；不按模型名称猜测容量。
- 新增可选的 `context-input-ratio`，默认 `0.8`，允许范围为大于零且不超过一。输入估算同时受占比限制和完整输出预留约束：

  `输入上限 = min(floor(上下文总容量 × 输入占比), 上下文总容量 − max-tokens)`

- 直接模型调用和工具循环均检查上下文；工具结果回填后的下一次请求重新估算，超限时拒绝新增模型调用，已发生的工具动作不回滚。
- 输入估算复用现有估算器。默认按完整消息、工具定义及透明状态的 UTF-8 JSON 字节加开销保守计数；应用提供自定义估算器时共用同一口径。
- 上下文策略随本轮模型参数快照固定，配置热更新不改变已开始轮次的容量声明；容量及比例只用于本地准入，不作为供应商请求字段发送。网页模型配置表单同步提供这两个字段。

## 记忆整理

- 合法的大输入不再被小于允许输入容量的固定总 token 配额阻塞，记忆生成完整继承模型输出额度；中期摘要仍优先生成简短正文。
- 模型截断、预算不足、输入超限或输出结构无效时，不以失败候选提交中长期记忆，也不推进整理进度；未完成批次继续沿原持久状态和退避规则重试。
- 本版本不将部分 JSON 当成成功结果，也不把扩大输出额度解释为必然消除供应商截断。完整结果仍须通过准入、来源、容量、租约及提交校验。

## 网页聊天

- 聊天页顶部新增“创建私聊”“创建模拟群”入口，直接打开创建表单并预选聊天类型；创建成功后自动进入新聊天。
- 每个档案仍只对应一个私聊；模拟群可选择多位已有档案。创建聊天不自动登记 Agent、变更记忆绑定或提升聊天角色权限。
- 创建响应中断时保留原操作编号与参数；关闭弹窗后可通过原请求重试入口继续确认，避免重复创建。
- 聊天配置中的群聊、私聊与其他功能增加本地矢量图标，类型文字继续保留；未知类型使用“其他”展示。

## 升级要求

1. 在 `config/agent/model.yml` 中，为每个实际使用的模型填写正数 `max-tokens` 和真实的 `context-window-tokens`。`max-tokens` 不得超过上下文总容量；`context-input-ratio` 可以省略，默认 `0.8`。缺少容量声明的模型会明确报告配置未就绪。
2. 检查自定义的 `tea-neko.llm.interaction.max-total-tokens`、`tea-neko.agent.summary.max-total-tokens` 和 `tea-neko.agent.personality-learning.max-total-tokens`。显式额度继续有效，必须能容纳完整输入估算和输出额度；希望只按模型容量准入时，可移除相应自定义总配额。
3. 使用本版本构建包启动；后续网页修改模型配置仍须分别执行保存和应用，旧文件代次的参数继续拒绝使用新凭据。

配置细节和完整示例见[模型配置说明](../../src/main/java/org/zexnocs/teanekoagent/llm/file_config/README.md)、[交互预算](../../src/main/java/org/zexnocs/teanekoagent/llm/framework/interaction/README.md)及[网页聊天](../development/web-console-chat.md)。
